## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ordered by the human in the session, 12 Nov 2026, answering CF-188's action 1: "Fix before release". CF-188's pull request #154 is held until this is ready to merge with it.

From CF-188's round-1 review (flush.ts around line 610 at 161b8fd): the carry commit that keeps held-back changes only reaches the state branch when `restartState` succeeds. If the restart fails (lock timeout, a reset --keep conflict, a non-board commit gained during the push), `rebaseError` is set and the state branch stays on the old state tip, while the pushed flush commit already records `From coder-fleet/state at <stateTip>`. The next flush's `changesSince` starts at that tip, so every change skipped before it is never judged again; the next successful restart then rebuilds the state branch from the tip plus the changes since, which reverts each skipped path to the tip's version on the state branch, and `reset --keep` writes that older version into the live board's files. docs/board-config.md step 4 says skipped changes stay on the state branch and the next flush judges them again; on this path they do neither.
