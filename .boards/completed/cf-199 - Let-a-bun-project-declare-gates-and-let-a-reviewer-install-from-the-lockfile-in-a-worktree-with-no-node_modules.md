## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ordered by the human, 12 Nov 2026, from a real project: an app built with bun hit "Gates: bun cannot be a gate (the reviewer's hook refuses package managers), so `bun test` cannot be declared". He asked "how can we fix this", chose "allow bun", then, asked what a review should do in a worktree with no node_modules, answered "Install from the lockfile, including the reviewer".

Today `REVIEWER_PACKAGE_MANAGERS` in claude/coder-fleet/hooks/enforce-agent-scope.sh refuses `bun` as a gate's first word, and docs/limits.md records "Go, Rust, Deno, bun and uv projects cannot declare gates", naming a per-tool offline flag as the way out. `bun --no-install` (bun 1.4.4: "Disable auto install in the Bun runtime") stops bun fetching missing imports, but in a worktree with no node_modules a test that imports a dependency then fails to resolve, for bun and Node alike. Since CF-193.6 a red declared gate starts a fix round, so a red caused by missing dependencies would commission a pointless fix. Hence the second half: the reviewer may install, but only a frozen-lockfile install with install scripts off, only at the top of a linked worktree that has no node_modules, and nothing else.

This loosens the reviewer's \"never install anything\" invariant and changes the scope hook, the fleet's authorisation layer: it gets the deeper review and a second round.
<!-- SECTION:DESCRIPTION:END -->

Decision and change by the lead, at the human's explicit order, 12 Nov 2026: "I am explicitely asking you, the lead, running Fable, to resolve this issue and not pass it on", the issue being that the install check's config-path reader (YAML and TOML read in bash) kept leaking: nine automated security passes, each a new form missed.

Resolution, commit d2ae61a0 on PR #169: the reader is removed, not patched. What stays: package-manager config must be the main checkout's HEAD by content hash, case-folded, no symlinks, no hidden index flags, and package.json's non-ordinary fields must match. What goes: following the paths that config names (yarnPath, plugins, preload, pnpmfile). Reason: the check defended a boundary the fleet does not have. A reviewer's gates run the diff's own code one command after the install, in the same sandbox (already recorded in docs/limits.md), and the coder ran the same install on the same code before the review began; an install that runs a diff-changed file named by trusted config adds no exposure those two do not already carry. A bash reader that is incomplete reads as a guarantee and is not one. docs/limits.md now states the boundary and names what would truly close it (a real parser in the hook, or installing where the diff's files are absent), each its own item. The contract pins that the hook neither follows such a path nor refuses config for its form, and that changing the config or anything under a compared entry is still refused. Suite at d2ae61a0: check-all.sh exit 0, scope-hook-contract 1063 passed.

This replaces the coder's Blocker question on the same point; the human's order answers it. Because the lead wrote this commit, its gates are taken from review-round's lanes, not the lead's own run.

Coder's proposals, not filed: let a use-mode reviewer run the same install; decide whether config already on main (a pnpmfile, a yarnPath) should be trusted.
