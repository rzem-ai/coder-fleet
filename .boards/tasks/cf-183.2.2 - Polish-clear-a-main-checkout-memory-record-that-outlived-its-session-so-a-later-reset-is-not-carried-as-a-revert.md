## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
What was still open on CF-183.2.1 after its review round, fix round and narrow second review (round 2 on d2e7bd5..7096e1c, 12 Nov 2026, approve with follow-ups). Filed by the lead under its end-of-rounds rule; not ordered by the human, so it waits for his go.

memory-state.py:405: once a checkout has handed a copy over, only a copy equal to that record counts as nothing new. `restore()` normally deletes the main checkout's memory-base record when the session ends (line 807), so a surviving record means SessionEnd never ran (a killed session) or restore gave up. If the human then puts the memory file back to the HEAD copy (git checkout or git restore) and a later stop runs, harvest sees a copy that differs from the record, takes the HEAD copy over the state copy, and silently drops other sessions' unflushed lines from coder-fleet/state before the next flush. They stay in the state branch's history. Before 1786f44 this path was a no-op. Traced by the reviewer by reading the code, not reproduced.
