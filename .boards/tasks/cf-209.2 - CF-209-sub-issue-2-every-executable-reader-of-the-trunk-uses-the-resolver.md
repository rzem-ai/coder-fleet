## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace each executable place that works out the trunk from `origin/HEAD`, or hard-codes `main` and `master`, with sub-issue 1's resolver. With `baseBranch` unset nothing changes.

The sites (paths under claude/coder-fleet/, lines as of 2026-11-14):
- `hooks/main-fast-forward.sh:155-157` - the session-start fetch and fast-forward target. Contract: `claude/evals/lib/fast-forward-contract.sh`.
- `scripts/prune-worktrees.sh:111-120` - builds `DEFAULT_REFS` for the ancestor check that decides whether a worktree is merged and may be removed. Contract: `prune-worktrees-contract.sh`.
- `workflows/review-round.js:1167` and `:1232` - a lane agent is told to find the default branch by `git symbolic-ref --short refs/remotes/origin/HEAD`, then `main`, then `master`; the answer is the diff base for a target-mode review (`:354`, `:1125`, `:1292`). The workflow reads `.claude/coder-fleet.json` through a lane agent on its own (`:389`, `:845`), not through the shared reader. Tests: `claude/evals/lib/workflow-logic.mjs`.
- `hooks/enforce-agent-scope.sh:1443-1444` - fleet-steward's "no push to a default branch" matches the literal words ` main`, ` master`, ` refs/heads/main`, ` refs/heads/master` in the command. Contract: `scope-hook-contract.sh` (`:1139`, `:1144`).

Not in this sub-issue, because CF-207 criterion 50 removes them: `board/src/flush.ts` `defaultTip()`, `board/src/state-worktree.ts` `defaultBase()` and `fetchRemoteOf()`, `scripts/board-git-check.sh`, `hooks/state-push.sh`, `hooks/lib/memory-state.py`.

One thing a named trunk changes that `origin/HEAD` never did: the human commits on the base branch himself, so it is routinely ahead of its remote copy, and it may have no remote copy at all. The fast-forward hook already leaves a branch that is ahead alone; this sub-issue keeps that and adds the no-remote-copy case.

Agent worktrees are cut from the lead's HEAD (`/init` sets `worktree.baseRef` to `head`), so they follow the base branch only while the main checkout is on it.

## Acceptance Criteria

- [ ] #1 With `baseBranch` set, `main-fast-forward.sh` fetches and fast-forwards that branch and no other, and its one-line report names it; `fast-forward-contract.sh` has a case where the remote's HEAD names `main`, `baseBranch` names another branch, and `main` is left untouched.
