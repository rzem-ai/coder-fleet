## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Card gate: when a coder or scripter bound to a card stops, or a task whose subject carries `[board:<id>]` completes, and every criterion and Definition of Done item is ticked, a hook moves the card to Done; no other agent's stop does; apart from the human's override no route moves an unticked card into Done, and a refusal names the unticked items (spec 29)
- [x] #2 The project's test command is set in the board's config under `~/.config/boards`, not in the repo (spec 30)
- [x] #3 A release names its cards in its annotated tag's message, on one line `Cards: CF-1, CF-2`; a tag with no such line moves nothing (spec 31)
- [x] #4 A successful in-session `git push` of a release tag starts the test gate for the named cards; a push made outside any session is caught at the next session start via `git ls-remote --tags`; tested by pushing from a shell then starting a session (spec 32)
- [x] #5 Every test run the board makes is recorded in the event trail with its commit and result; a recorded green run for the tagged commit moves the named Done cards to Released at once, otherwise the suite runs in the background against the tagged commit in a temporary worktree and the cards move when it passes (spec 33)
- [x] #6 A background run's log is kept beside the board, survives its session and can be read through the CLI and web UI during and after the run; a run whose process vanished without a result restarts at the next session start (spec 34)
- [x] #7 A failed run moves the named cards to Blocked, with the run's output added as a comment (spec 35)
- [x] #8 The push and the session's turn never wait for the suite: the pushing turn returns before the run finishes, measured against a test command that sleeps longer than the turn takes (spec 36)
- [x] #9 A card named by a release but not in Done stays where it is, and the release's result says so (spec 37)
- [x] #10 Released is the final column: only the human, in the web UI, can move a card out of it (spec 38)
<!-- AC:END -->
