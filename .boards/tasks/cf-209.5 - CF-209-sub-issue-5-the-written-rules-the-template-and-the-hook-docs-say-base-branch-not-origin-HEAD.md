## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Once the settings are honoured and the local landing exists, bring every piece of prose an agent or the human reads into line, so nothing still tells the lead that the trunk is what `origin/HEAD` points at or that work always lands through a pull request.

The prose sites (paths under claude/coder-fleet/, lines as of 2026-11-14):
- `skills/lead-procedures/SKILL.md:127,129,131` - Worktrees and memory: "The default branch is what `origin/HEAD` points at, as `prune-worktrees` reads it", the fetch and `--ff-only` recipe, and the list of reasons the session-start hook is silent.
- `commands/prune-worktrees.md:2,7,15,37` - "The default branch is what origin/HEAD points at, or main when there is no remote."
- `commands/sweep.md:2,6,12,16` - the sweep's range ends at the default branch's head, defined the same way.
- `commands/init.md:22` and `commands/kickoff.md:18` - the `worktree.baseRef` note, "cuts every agent worktree from origin/<default-branch>".
- `commands/drain.md:18` - "the gates red on the default branch".
- `agents/lead.md` step 1 and step 5, `agents/fleet-steward.md:39`, and `templates/AGENTS.md:56-58`.
- `hooks/README.md:10,24,229,362,366,442,655` and `hooks/hooks.json:2`.
- Root `AGENTS.md` and `claude/README.md`, where they describe the trunk or shipping.
- The OpenCode port: a row in `opencode/docs/divergence-register.md` if the port does not carry the settings.

Not in this sub-issue: text about the state branch never reaching the default branch (`agents/coder.md:45`, `agents/scripter.md:47`, `skills/help-boards/**`, `skills/glossary/SKILL.md:25`, `commands/flush.md`), which CF-207 criterion 53 rewrites.

Whether the glossary gains a "Base branch" row is a judgement for the builder to raise, not to make: a new term is a glossary change, which regenerates the rule.

This changes agent bodies and skills, so the `migration-checklist` runs before its pull request opens. Sequenced after the CF-207 groups that rewrite the same files, as sub-issue 4 is.
