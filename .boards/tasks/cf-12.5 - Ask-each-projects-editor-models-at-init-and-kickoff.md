## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of CF-12 (spec docs/specs/CF-12.md: Decisions Q3, Q8, Q9, Q12, Q16; "The Fable rule" wording requirements). /init asks two separate questions, one per editor - Opus (default), Fable, or neither - with the Fable option saying Pro plans exclude Fable, Fable draws on the shared weekly cap, and for the tech editor that it runs on every tech-writer document. The answer is recorded in the project's AGENTS.md; .claude/settings.json gets permissions.deny rules for every unchosen definition (both for neither) without touching other keys. /kickoff asks only when AGENTS.md records no answer. The lead reads the record to pick which definition to spawn. Depends on CF-9, which also edits kickoff.md and init.md, and on CF-12.1's finding on whether the deny rule matches a plugin agent. The OpenCode register rows and the Codex note land here.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `/init` asks two separate questions, one per editor, each offering Opus (default), Fable and neither with AskUserQuestion. The Fable option says Fable draws on the shared weekly cap; that on Pro it is billed to usage credits, possibly without asking, which is inferred from the docs and not observed; and, for the tech editor, that it runs on every `tech-writer` document.
- [ ] #2 For each editor's answer, `/init` records it in the project's `AGENTS.md` and writes deny rules to `.claude/settings.json` without touching any other key, following init's existing merge rule: Opus denies the `-fable` definition, Fable denies the unsuffixed definition, and neither denies both.
- [ ] #3 `/kickoff` asks the same questions, and writes the same record and deny rules, only when `AGENTS.md` records no answer. It asks nothing when an answer is recorded.
- [ ] #4 For each of the three answers, a recorded manual run shows a spawn of a denied definition by its `coder-fleet:` name refused with the "has been denied by permission rule" error, and a spawn of the chosen definition running.
- [ ] #5 Where the fleet documents the deny rules, it says a spawn by the bare name, such as `spec-editor-fable` without the prefix, reads "not found" whether or not a rule exists, which is expected and not a sign the rule failed.
- [ ] #6 The lead reads the project's `AGENTS.md` record to pick which editor definition to spawn, whether to fall back to its own pass (Q13), and whether the gate applies, and treats no record as no spec editor and no gate (Q21).
- [ ] #7 The OpenCode divergence register has a row for each of the four agents, and the Codex docs carry a note that the editors are a later port decision.
- [ ] #8 `bash claude/evals/lib/instruction-file-contract.sh` passes.
- [ ] #9 The version is bumped in `claude/coder-fleet/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
