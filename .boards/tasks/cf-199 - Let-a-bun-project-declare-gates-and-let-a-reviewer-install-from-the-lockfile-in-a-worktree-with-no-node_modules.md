## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Ordered by the human, 12 Nov 2026, from a real project: an app built with bun hit "Gates: bun cannot be a gate (the reviewer's hook refuses package managers), so `bun test` cannot be declared". He asked "how can we fix this", chose "allow bun", then, asked what a review should do in a worktree with no node_modules, answered "Install from the lockfile, including the reviewer".

Today `REVIEWER_PACKAGE_MANAGERS` in claude/coder-fleet/hooks/enforce-agent-scope.sh refuses `bun` as a gate's first word, and docs/limits.md records "Go, Rust, Deno, bun and uv projects cannot declare gates", naming a per-tool offline flag as the way out. `bun --no-install` (bun 1.4.4: "Disable auto install in the Bun runtime") stops bun fetching missing imports, but in a worktree with no node_modules a test that imports a dependency then fails to resolve, for bun and Node alike. Since CF-193.6 a red declared gate starts a fix round, so a red caused by missing dependencies would commission a pointless fix. Hence the second half: the reviewer may install, but only a frozen-lockfile install with install scripts off, only at the top of a linked worktree that has no node_modules, and nothing else.

This loosens the reviewer's \"never install anything\" invariant and changes the scope hook, the fleet's authorisation layer: it gets the deeper review and a second round.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A reviewer may run `bun --no-install test` as a declared gate, with the one path or test-name filter the `test` gate already allows; every other bun or bunx form (install, add, remove, update, x, run, link, pm, bunx) is still refused as a gate
- [ ] #2 Evidence that `bun --no-install test` in a directory with no node_modules does not fetch: it fails to resolve an uninstalled dependency rather than installing it, shown by a test or a recorded run with an empty bun cache
- [ ] #3 A reviewer may run exactly one install form per lockfile, frozen and with install scripts off, chosen by the lockfile present: bun.lock or bun.lockb, package-lock.json, pnpm-lock.yaml, yarn.lock; and only at the top of a linked worktree with no node_modules, never in the main checkout
- [ ] #4 Each near miss is refused: an install that is not frozen, with scripts on, with a package name, in the main checkout, outside the worktree's top, where node_modules already exists, or for a lockfile the worktree does not have
- [ ] #5 scope-hook-contract.sh has a case for every allow and every near miss above, and at least one case fails if the install allow is removed
- [ ] #6 If a gate still cannot run because dependencies are missing (no lockfile, or the install failed), review-round lists it as not run with that reason rather than as failed, so it starts no fix round, with a workflow logic test
- [ ] #7 reviewer.md, docs/limits.md and templates/AGENTS.md say what a reviewer may now install and how a bun project declares its test gate, and the limits entry no longer names bun
- [ ] #8 `bash claude/evals/lib/check-all.sh` passes
