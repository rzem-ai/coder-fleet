## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Sub-issue 3 of 4 of CF-24 (spec docs/specs/CF-24.md, approved 2026-09-30). One check in `Core.createTaskFromInput` holds on all three create paths: the CLI, MCP task_create and the web endpoint (finding 5 in the deleted plan). The refusal covers Drafts too (OQ5). As with sub-issue 2, the new config key must go through `serializeConfig`, or a config save drops it. It is a boolean key, so add it to `BOOLEAN_CONFIG_KEYS`.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 (CF-24 #6) With the config requiring criteria, creating an item with none is refused on the CLI, MCP task_create (as a tool error) and web UI paths, with a message naming the key; unchanged when the key is absent or off; fork tests fail first
- [ ] #2 (CF-24 #7) This repo's .boards/config.yml and templates/board.config.yml switch the require-criteria key on; the template says how to turn it off, and /init step 2b says it is on and where to change it
- [ ] #3 check-all.sh passes, new fork tests are in BOARD_TESTS, and the version is bumped in both manifests
