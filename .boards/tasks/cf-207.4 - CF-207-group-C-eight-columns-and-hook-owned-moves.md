## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A board has exactly eight columns, in this order: Draft, Backlog, Next, In Progress, Done, Released, Blocked, Blocked by Human (spec 17)
- [ ] #2 Anyone can file a card into Draft and move a card out of Draft, and a card leaving Draft goes to Backlog only; a move from Draft anywhere else is refused through every interface, the web UI included (spec 18)
- [ ] #3 A card can be filled into Next only through the web UI; the same move through an MCP tool or the CLI is refused, says why, and leaves the card where it was; a hook returning a card to Next is a return, not a fill, and is allowed (spec 19)
- [ ] #4 The human orders Next in the web UI, and an agent asking for work is given the top card of Next first (spec 21)
- [ ] #5 No MCP tool or CLI command sets a card's column directly except Draft to Backlog; every other column change is made by hooks, gates or the human in the web UI; ticking a checklist item never moves a column (spec 22)
- [ ] #6 The human's web UI moves override the gates, except out of Draft other than into Backlog; every move that bypassed a gate writes an event log line naming the gate (spec 23)
- [ ] #7 Focus binding as coder-fleet does today: a focus file per checkout, inherited by a worktree spawned from it, also set by a `Board-Item:` line; cleared on a new, cleared or resumed session and kept across compaction; bound agents move only their card (spec 24)
- [ ] #8 An agent starting work on its bound card moves it to In Progress only from Backlog or Next; a start in any other column moves nothing and the event log says why (spec 25)
- [ ] #9 A `Blocker:` line in an agent's handoff adds an unticked Action for Human carrying the blocker text, and adding any Action for Human moves the card to Blocked by Human; a `Propose item:` line never moves a column (spec 26)
- [ ] #10 A card leaving Blocked or Blocked by Human returns to the column it was blocked from, read from the event trail; it leaves Blocked by Human once every Action for Human is ticked, and Blocked when the human moves it or a later release run naming it passes (spec 27)
- [ ] #11 The table of which hook event moves a card from which column to which is written in the board's documentation, and a test drives each event and checks the resulting column (spec 28)
- [ ] #12 Every column move goes through one function that takes the card's from column from the card itself (never from the caller), refuses a column name outside the eight, and holds the card's lock for the whole read-then-write, so the event trail never records a column the card was not in (from CF-207.7's review)
<!-- AC:END -->
