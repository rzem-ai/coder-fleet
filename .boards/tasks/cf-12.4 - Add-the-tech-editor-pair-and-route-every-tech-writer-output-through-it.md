## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Part of CF-12 (spec docs/specs/CF-12.md: Decisions Q4, Q5, Q13; "The four agents"). tech-editor and tech-editor-fable, generated from one source (CF-12.2), edit every tech-writer output in place inside tech-writer's scope, carrying tech-writer's invariants (no invented APIs, flags, paths or versions; unsupported claims go under Unverified). lead.md step 4 becomes: the project's tech editor on every tech-writer output when it has one, otherwise the lead's own opus pass on external-audience output only. Carries its own roster rows (design, README, hooks.json matcher, scope hook branches and contract cases, two evals, agent-contract counts). Sequenced after CF-12.3 because both edit lead.md and the scope hook.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `bash claude/evals/lib/check-all.sh` passes on the branch, and `roster-contract.sh` checks all fifteen bodies with no existing check weakened.
- [ ] #2 `tech-editor` and `tech-editor-fable` have `effort: medium`, `maxTurns: 15`, models `opus` and `fable`, a single-line tools allowlist with no `Bash`, `WebSearch` or `WebFetch`, and memory write tools under `disallowedTools`. The PR carries the `migration-checklist` findings for both.
- [ ] #3 Both tech-editor bodies tell the agent to make its next turn the four-heading handoff, with the unfinished work under Not done, when its turn budget is nearly spent, and the tech-editor eval's `checks.sh` greps for that instruction.
- [ ] #4 The scope hook denies either tech editor a write or edit outside `tech-writer`'s scope, and any Bash command. Each is proven by a scope-hook contract case that failed before the change.
- [ ] #5 The tech-editor eval has three to five prompts with a rubric and a baseline; at least one is a document that should come back substantially unchanged, and one carries an unsupported claim that must land under Unverified rather than in the prose.
- [ ] #6 `lead.md` step 4 matches Q13: the chosen tech editor on every `tech-writer` output when the project has one, and otherwise the lead's own opus pass on external-audience output only. The lead's model invariant is unchanged.
- [ ] #7 `docs/fleet-design.md` has the two tech-editor roster rows, and its section 4 escalation note says the lead's opus pass applies only when the project has no tech editor.
- [ ] #8 `tech-editor` and `tech-editor-fable` are generated from `claude/agent-pairs/tech-editor.md` by `gen-agent-pairs.sh`, and `gen-agent-pairs.sh --check` passes.
- [ ] #9 The version is bumped in `claude/coder-fleet/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
