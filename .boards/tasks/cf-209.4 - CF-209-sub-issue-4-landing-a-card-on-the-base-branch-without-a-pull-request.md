## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
With `push` restricted there is no pull request, so every step of the fleet that hangs off one needs a local equivalent: the review, the "ready to merge" comment, the merge, closing the card and removing the worktree.

What hangs off a pull request today (paths under claude/coder-fleet/):
- `skills/lead-procedures/SKILL.md:109-121`, Shipping: push the branch, open a draft pull request, review, `gh pr ready`, merge on GitHub once CI is green, tag, deploy, remove the worktree. Its default with no grant is "you push and open the pull request, and the merge is the human's" (also `agents/lead.md:34`, `templates/AGENTS.md:56-58`).
- `skills/lead-procedures/SKILL.md:25-29`, The card: the three comments' exact first line, `ready to merge in PR #<n>` and `merged to main at <sha>`, which `/drain` resumes from.
- `commands/drain.md:9,17`: opens the pull request, leaves the ready comment, finds the build by `gh pr list --state all --head <branch>`.
- `commands/triage.md:10`: a card is finished when its work is merged to the default branch.
- `hooks/board-merged-cards.sh`: names a card to close once every pull request in its ready comments has merged, read through `gh`.
- `scripts/prune-worktrees.sh:121-128`: removes a worktree only when its HEAD is an ancestor of the trunk, which a squashed landing never is.
- CI: with no pull request there is no CI run, so the gates run by a reviewer in the worktree are the only independent run.

How the work lands - one squashed commit per card or the builder's commits kept - is the human's answer to the parent card's Actions for Human.

Sequencing. CF-207 criteria 53 and 55 rewrite `lead-procedures`, `/drain`, `/triage` and `/kickoff`, and its clarifications drop `board-merged-cards.sh`. Build this sub-issue after those CF-207 groups merge, against the new board's columns and markers, or agree the order with whoever is draining CF-207.

This changes agent-facing skills and commands, so the `migration-checklist` runs before its pull request opens.

The human's answer in the fleet session, 14 Nov 2026, to the open Actions for Human entry: in a base-only project, a landed card counts as Released when the lead pushes the base branch carrying it. The test gate runs on that commit, and the card moves from Done to Released on a pass, or to Blocked on a fail.

This was given alongside CF-209 comment 5's `release` setting (off, tag or github), and for release: off the two read differently: comment 5 says cards end at Done, while this answer says the base push moves them to Released. The lead is asking the human which holds. The entry stays unticked until then.
