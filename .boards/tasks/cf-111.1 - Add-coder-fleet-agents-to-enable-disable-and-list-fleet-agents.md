## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The human's words (2026-10-04): "please add a `/` command to enable/disable an agent".

A plugin command, `/coder-fleet:agents`, that edits `.claude/coder-fleet.json` (`disabledAgents`, from CF-111) so the human never hand-edits JSON. The command markdown runs a deterministic script that does the edit; the model does not rewrite the file itself. It reuses CF-111's parsing and validation (core agents lead, coder, reviewer cannot be disabled) rather than duplicating it. It writes the file and does not commit; the human commits.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 `/coder-fleet:agents disable <name>` adds the agent to `disabledAgents` in `.claude/coder-fleet.json`, creating the file if absent, accepting a bare or `coder-fleet:`-prefixed name and storing it bare
- [ ] #2 `/coder-fleet:agents enable <name>` removes it, and leaves the file with an empty list (or removes the key) rather than breaking it; enabling an agent that is not disabled is a no-op that says so
- [ ] #3 `/coder-fleet:agents` with no argument lists every roster agent with its enabled or disabled state
- [ ] #4 Disabling lead, coder or reviewer, or an agent name not on the roster, is refused with a message and leaves the file unchanged
- [ ] #5 The edit is done by a script with a contract test under claude/evals/lib/ wired into check-all.sh, sharing CF-111's validation, and the command is documented in README alongside the config file
