## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The web UI listens only on a loopback address and is unreachable from another machine (spec 58)
- [ ] #2 It starts on request through the CLI or an MCP tool, which prints its tokened address to the human; a second session's request reuses the running server and port; the server stops when the last session using it ends (spec 59)
- [ ] #3 It does full editing: titles, descriptions, criteria and Definition of Done items, Actions for Human, comments and moves, under group C's column rules (spec 60)
- [ ] #4 Its look is the human's Ledger design (shadcn/ui), with its laptop, desktop and ultrawide boards, card detail, dark mode, and empty, dragging and loading states (spec 61)
- [ ] #5 The design's six columns are extended to the board's eight, adding no structure the design lacks (spec 62)
- [ ] #6 For each of the design's views and states, a screenshot of the running UI sits beside the design's own, and the human judges they match (spec 63)
- [ ] #7 After any operation through the web UI or the MCP tools, `git status` in the repo and each worktree shows no file written by the board (spec 2; CF-207.2 proved it for the CLI only, since neither existed then)
- [ ] #8 The web UI shows each card's move history in its card detail, from the event trail, and has no board-wide feed (spec 47; moved here from CF-207.7)
<!-- AC:END -->
