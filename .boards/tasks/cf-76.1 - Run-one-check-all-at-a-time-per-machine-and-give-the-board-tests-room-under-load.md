## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The human ordered this on 2026-10-07 ("implement these fixes") after the lead measured, on an idle machine: one check-all alone 86 s, all green; the board tests beside one check-all (load about 16 on 16 cores) 62 s, all 319 pass at the 10 s limit; two check-alls at once (load 58) 295 s each, and both fail the board section on 2 tests over the 10 s per-test limit. check-all runs its 36 sections at once and saturates the cores by design, so two runs starve each other; the hook contracts have no per-test timeout and pass, the board tests have a hard 10 s one and fail. Nothing is shared between two trees; it is CPU starvation meeting an absolute timeout. review-round's tests and types-and-build lanes both run check-all at once, which is why review lanes were red in the board section all day. The lead builds this itself under the size floor.

A background security scan of a5232fb flagged the default lock path as an insecure temp file: /tmp/coder-fleet-check-all-<uid>.lock in world-writable /tmp lets another account plant a symlink there, or take and hold the lock to stall every run up to its wait limit. Fixed in the next commit: the default is /tmp/coder-fleet-<uid>/check-all.lock inside a directory this user owns, mode 700; a directory that is a link or not this user's, or a lock path that is itself a symlink, is refused and the run goes unlocked. New contract case link-path fails without the symlink check (7 passed, 1 failed) and passes with it (8 of 8). The fix commit gets its own review after the round already running on a5232fb.
