## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Every card is one markdown file with YAML frontmatter. A repo's board lives in one directory, `~/.config/boards/<key>/`, holding its cards, config, event log, locks, test-run logs, specs and run articles (`runs/`); `$XDG_CONFIG_HOME/boards/<key>/` when XDG_CONFIG_HOME is set. Agent memory is not there: it stays in each checkout's .claude/agent-memory as Claude Code keeps it (spec 1)
- [ ] #2 After any operation through the MCP tools, the CLI or the web UI, `git status` in the repo and in each of its worktrees shows no file written by the board (spec 2)
- [ ] #3 A repo's main checkout and every linked worktree of it read and write the same board (spec 3)
- [ ] #4 A board is keyed by the repo's origin remote URL, so moving or re-cloning the repo on the same machine reaches the same board; SSH and HTTPS spellings of the same remote reach the same board (spec 4)
- [ ] #5 A repo with no origin remote gets a board keyed by the absolute path of its shared git directory, used from the main checkout and every worktree; when it later gains an origin remote, its board moves to the URL key once (spec 5)
- [ ] #6 A fork, whose origin is the fork's own URL, gets its own board, separate from the upstream repo's (spec 6)
- [ ] #7 A board is created only through the CLI or the web UI, which ask the human for the board's id prefix; an agent in a repo with no board gets a message telling it to ask the human to create one (spec 7)
- [ ] #8 Card ids are the prefix, a dash and a number (`XY-12`); sub-issues carry dotted ids (`XY-12.1`); a number is never reused, including after a card is deleted (spec 8)
- [ ] #9 Anyone may delete a card through any interface; its file goes and the event log keeps a line for the deletion (spec 9)
- [ ] #10 When no board can be found for the session, the board's hooks do nothing and say so once per session (spec 10)
<!-- AC:END -->
