## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the two keys to `.claude/coder-fleet.json` and give the plugin one place that answers "which branch is the trunk" and "what may be pushed", so sub-issues 2 and 3 have something to call. Nothing changes behaviour for a reader yet: this sub-issue adds the settings, the resolver and the command, and wires no hook to them.

Where it goes (paths under claude/coder-fleet/). The shared reader is `hooks/lib/fleet-config.py` (keys `phase`, `disabledAgents` today, "Other top-level keys are ignored") behind `hooks/lib/fleet-config.sh`. The file is written only by `scripts/fleet-agents.sh`, driven by `commands/agents.md`, which tells every agent never to edit the file itself. Contract tests: `claude/evals/lib/disabled-agents-contract.sh` for the reader and `agents-command-contract.sh` for the command.

The resolver's order: `baseBranch` when set; otherwise what the remote's HEAD names, the remote being `origin` or the only remote, as `main-fast-forward.sh` reads it today; otherwise `main`. Today five places each do the last two steps on their own.

The values `push` takes are fixed by the human's answer to the parent card's Actions for Human on who pushes the base branch; `all` is the name for today's behaviour either way.
