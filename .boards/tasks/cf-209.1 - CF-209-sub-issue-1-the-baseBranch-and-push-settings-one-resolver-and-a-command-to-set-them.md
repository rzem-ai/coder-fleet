## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the three keys to `.claude/coder-fleet.json` and give the plugin one place that answers "which branch is the trunk", "what may be pushed" and "does this project release", so sub-issues 2, 3 and 4 have something to call. Nothing changes behaviour for a reader yet: this sub-issue adds the settings, the resolver and the command, and wires no hook to them.

Where it goes (paths under claude/coder-fleet/). The shared reader is `hooks/lib/fleet-config.py` (keys `phase`, `disabledAgents` today, "Other top-level keys are ignored") behind `hooks/lib/fleet-config.sh`. The file is written only by `scripts/fleet-agents.sh`, driven by `commands/agents.md`, which tells every agent never to edit the file itself. Contract tests: `claude/evals/lib/disabled-agents-contract.sh` for the reader and `agents-command-contract.sh` for the command.

The resolver's order for the trunk: `baseBranch` when set; otherwise what the remote's HEAD names, the remote being `origin` or the only remote, as `main-fast-forward.sh` reads it today; otherwise `main`. Today five places each do the last two steps on their own.

The values, as the human settled them on CF-209 (comments 2 and 5):
- `push`: `all` (today's behaviour, and what unset means) or `base-only`.
- `release`: `off`, `tag` or `github`. Unset is its own state, meaning today's behaviour where the project's shipping words decide, so the reader has to tell unset from `off`.

Failing closed. Each of `push` and `release` guards something that reaches a remote, so a value the reader cannot understand resolves as the strictest one: `base-only` for `push`, `off` for `release`.

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 `.claude/coder-fleet.json` accepts a `baseBranch` string, a `push` value of `all` or `base-only` and a `release` value of `off`, `tag` or `github`, and the shared reader in `hooks/lib/fleet-config.py` returns all three alongside `phase` and `disabledAgents`, with a file that sets none of them read exactly as it is today.
- [x] #2 One resolver, callable from a shell hook and a script, prints the trunk for a checkout: `baseBranch` when set, else the branch the remote's HEAD names, else `main`; a contract test covers each of the three with the remote's HEAD pointing somewhere else.
- [x] #3 A `baseBranch` that is not a valid branch name, or that names no local branch, a `push` value outside its set and a `release` value outside its set are each reported as invalid naming the key and the value, and the reader's callers can tell invalid from unset for each key.
- [x] #4 An invalid or unreadable `push` value resolves as `base-only`, never as `all`, and an invalid or unreadable `release` value resolves as `off`; a contract test pins each.
- [x] #5 `/coder-fleet:agents` shows the current base branch, push policy and release setting with where each came from (the setting or the fallback), and sets or clears each one through `scripts/fleet-agents.sh`, writing the file as it writes `phase` today.
- [x] #6 `docs/board-config.md` or the document that describes `.claude/coder-fleet.json` names all three keys, their values, what unset means for each, and that the three are independent.
- [x] #7 An unset `release` is reported as unset, distinct from `off`, so a project that never sets it keeps today's behaviour; a contract test covers unset, each of the three values and an invalid one.
