description: Go through the cards In Progress, Blocked and Blocked by Human - close the In Progress ones that are fully ticked and merged, report where the rest stand, and ask the human multiple-choice questions to unblock the blocked cards and answer the open Actions for Human, recording each answer on its card
---

Triage the board for the human: close what is finished, say where the rest stand, and ask what unblocks the stuck cards. It is named `triage` because Claude Code's built-in `/status` shadows a plugin command of that name. It starts no build and writes no column. A fully ticked card normally reaches Done without triage: the card gate moves it when the `coder` or `scripter` bound to it stops. Triage closes what no stop closed, through the closing task in step 3, which the `TaskCompleted` hook's card gate checks. Done is not the end: a release whose annotated tag names the card on its `Cards:` line moves it to Released once the suite passes, and that is the lead's release, not triage.

## Procedure

1. List In Progress, Blocked and Blocked by Human with `card_list`, one call per column, then read each card with `card_read`: its acceptance criteria, Definition of Done, Actions for Human, comments, sub-issues and any pull request the comments name. A card in Draft, Backlog, Next, Done or Released is out of scope. If the board tools are not available, say the board's MCP server is not loaded and why, as `work` does, and stop.
2. Decide each In Progress card. It is finished only when it has at least one acceptance criterion, and every acceptance criterion and every Definition of Done item, the board's defaults included, is already ticked and its work is merged to the default branch, with every sub-issue and named pull request merged; check the merge with `git` or `gh`, never from a comment's say-so. Work landed without a pull request, under `push: base-only`, counts as merged when the commit each `landed on <base> at <sha>` comment names is on the default branch, which `git merge-base --is-ancestor <sha> <base>` answers. A card with no acceptance criterion is never closed; report it in step 4 instead. Triage never ticks a criterion and never runs the suite to prove one.
3. Close each finished card through a task, never a column write. Create a task with `TaskCreate` whose subject carries the `[board:<id>]` marker, for example `Close CF-12 [board:CF-12]`, then complete it with `TaskUpdate` so the `TaskCompleted` hook runs the card gate, which moves the card to Done only when every item on it is ticked. If the gate holds it, the card stays where it is and the board's event trail records why, which `${CLAUDE_PLUGIN_ROOT}/boards/boards.sh history <id>` prints: report the hold for that card with the unticked items `card_read` shows, and do not retry. If `TaskCreate` or `TaskUpdate` is missing, `CLAUDE_CODE_ENABLE_TODO_TOOLS` is probably unset (the `help-boards` skill says more): name each finished card and ask the human to move it in the web UI, which `board_web` opens.
4. Report every other In Progress card as one entry, in the human's terms. Done: what is ticked and merged. Not done: the unticked criteria and Definition of Done items by number, counted from 0, and each sub-issue or pull request not yet merged. Say so plainly when a card has no progress at all.
5. Build the questions, then ask them with AskUserQuestion, at most four questions per prompt, in as many prompts as it takes:
   - Each card in Blocked gets one question built from its comments: what it is waiting on - a failed release run's output is one - with two to four options, the recommended one first and marked `(Recommended)`. A card with no such comment still gets a question, with options such as giving it a decision the human types, leaving it, or moving it back by hand in the web UI.
   - Each unticked Action for Human on a card in In Progress, Blocked or Blocked by Human gets one question, built the same way. A card in Blocked by Human is there because of its open actions, so its actions are its questions.
   - Skip a question when a comment on the card records a leave it answer for that same action (or for a Blocked card's blocker), unless the card changed since that comment. A leave it on one action does not skip the card's other actions.
6. Record each answer on its card straight away. An answered action is ticked with `card_tick` (list `actions`, its number from 0), with a `card_comment` that names the action's number and quotes the human's answer; once every action is ticked, the board's next hook takes the card back to the column it was blocked from. A Blocked card's answer is a comment quoting the answer. A leave it answer is a decision: record it as a comment on the card that names the action's number, or says it is the card's blocker (an action stays unticked), so the next run does not ask it again. Only a question the human skipped goes unrecorded. Never move a card's column and never start a build; the human orders that, or `drain` picks it up.
7. End with one line, exactly in this shape, writing an empty group as `0 closed (-)` and so on:

   `Triage: <n> closed (<ids>), <n> held (<ids>), <n> reported (<ids>), <n> questions asked (<ids>), <n> answers recorded (<ids>).`
