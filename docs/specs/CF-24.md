## Problem

- **Criteria are written but not ticked, and nothing refuses Done while they are unticked.** `lead.md` step 5 has required a tick naming the test since v0.27.9 (`lead.md:33`), and it ran on CF-3 (CF-3 card, lines 105, 111 and 244). But the `TaskCompleted` hook reads no criteria: on a passing gate it moves the item to Done without looking at the card (`claude/coder-fleet/hooks/board-task-completed.sh:183-188`). CF-64 reached Done on 2026-09-29 with all five of its criteria unticked (CF-64 card, lines 23-27). A rule the lead has to remember is not enough; this is why Q3 chose machinery.
- **Definition of Done is never written.** The fork supports project defaults through `definition_of_done:` in `.boards/config.yml` (`claude/coder-fleet/board/src/file-system/operations.ts:2144`, rechecked 2026-09-30), and applies them only when an item is created (`claude/coder-fleet/board/src/core/backlog.ts:1396-1398`). Neither this repository's `.boards/config.yml` nor `claude/coder-fleet/templates/board.config.yml` sets the key (both read 2026-09-30).
- **Nothing refuses an item with no criteria.** MCP `task_create` requires only `title`, and no config key exists to require criteria (no `require_acceptance` anywhere under `claude/coder-fleet/board/src`, 2026-09-30).
- **No rule says who ticks a Definition of Done item.** `docs/agent-contract.md:80` now names the lead's board writes, including ticking criteria, but not Definition of Done items; `docs/fleet-design.md` section 7 and board-conventions say nothing about ticks.
- **[revised 2026-09-30]** Two 2026-09-27 bullets are gone. "Plans have no Done when" and "the card and the plan can diverge silently" described plans, which no longer exist (CF-58). With the card as the only statement of what finishes an item (Q7), the divergence cannot happen.
