# The lead's procedures live in its body and in reference files

`claude/coder-fleet/agents/lead.md` carries the procedures every order needs: taking an order, what a card carries before the first spawn, its three comments and its ticks, briefing and spawning, the challenge gate, the review rules that apply to every change, merging handoffs, the default shipping steps, keeping the base branch level, removing merged worktrees and where memory lives. What applies only sometimes is in plain files under `claude/coder-fleet/references/`, one per topic, each opening with the step of the body that sends the lead there; the body names each by `${CLAUDE_PLUGIN_ROOT}/references/<file>` at that step, and the lead reads it then and never all at once. This record says why, and why each contract check that fixes the lead's shape is what it is (CF-48.3).

## Why the body

Claude Code loads no `skills:` for an agent run as the session. Seen on 2.1.325 in an interactive session and under `claude -p --agent` (`docs/limits.md`): the lead, set with `"agent": "coder-fleet:lead"` in project settings, starts with its body and none of the skills its frontmatter lists. A skill that sets `disable-model-invocation: true` cannot be loaded through the Skill tool either, so a procedures skill kept out of discovery reaches the lead only if it reads the file. The body is the one text that always loads, and it survives a compaction, so the procedures every order needs go there. A `SessionStart` hook that injects them was the alternative, and the human chose the body over it.

`${CLAUDE_PLUGIN_ROOT}` is substituted in an agent's body, as the challenge-gate command in step 3 shows in a live session, so a reference path the body names resolves to the installed plugin's copy and the lead can Read it. The reference files are not skills, because a skill wrapper the lead cannot load is the problem being fixed. They live in their own directory at the plugin's top level, outside `agents/` and `skills/`, which Claude Code scans for definitions.

`help-boards` sets no `disable-model-invocation`, so the body has the lead load it with the Skill tool, as `coder-fleet:help-boards`, before its first board action of a session; the body then states no board mechanic that skill already carries. The glossary reaches the lead as the project's rule, `.claude/rules/glossary.md`. The handoff's four headings and two typed lines are named in the body's Handoff section, which is all the lead needs to reject a malformed result. The frontmatter still lists `glossary`, `handoff` and `help-boards`, because the roster expects the first two and the list costs nothing while it is not loaded; the body depends on none of it.

## Why a size cap instead of a line cap

The 60-line cap and the no-hard-wrap rule (`docs/agent-contract.md` sections 3 and 4) were written for bodies whose procedures sit in a preloaded skill. Under them every rule the lead gains makes an existing line longer, and a step that grows into a single-paragraph wall signals a rule's scope and priority only by its place in a sentence, which current guidance for the models that run the lead says reduces quality. So the lead's steps open with the decision on the numbered line and carry the procedure in indented paragraphs below it, and the lead's cap is its size, 20 KB, with no paragraph over 250 words. The size cap is what keeps the body from re-accreting; what would push it over goes to a reference file.

## The checks

- `claude/evals/lib/roster-contract.sh`: every body but the lead's is under 60 lines; the lead's is at most 20,480 bytes, no paragraph of it runs past 250 words, every `${CLAUDE_PLUGIN_ROOT}/references/<file>` it names exists, every file under `references/` is named by it, and each opens with a line naming the step that sends the lead there. The four sections and the `glossary` and `handoff` preloads are checked for the lead as for every agent. `claude/evals/lib/roster-readme-fixture.sh` sets `LEAD_BODY_OVERRIDE` to a copy of the body over 20 KB, to one carrying a paragraph over 250 words and to one naming a reference file that does not exist, and requires each to fail the check that guards it.
- `claude/evals/lib/requirements-source-contract.sh`: step 2 keeps `2. Route by job:` and the five phrases it pins on that numbered line, because routing on a requirements source is a decision, and the six-step count still catches a lead that loses a step; the indented paragraphs are not counted as steps.
- `claude/evals/lib/workflow-logic.mjs`, `challenge-same-script-in-lead`: step 3's numbered line keeps the exact challenge-gate command, since when to run it is the step's decision.
- `workflow-logic.mjs`, `mutant-cap-one-phrase`: `at most eight mutants` is required in `references/break-mode.md`, where the break-mode brief lives, beside `agents/reviewer.md`.
