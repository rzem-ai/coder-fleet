## Setup

Three throwaway projects under the session scratchpad, one per answer, each holding the template `AGENTS.md` and a `.claude/settings.json` of `{}`. The deny rules were written by the same command `/init` step 2c runs, once per editor:

```
python3 -I <worktree>/claude/coder-fleet/scripts/editor-models.py set spec <answer> --root <scratch>/projects/<answer>
python3 -I <worktree>/claude/coder-fleet/scripts/editor-models.py set tech <answer> --root <scratch>/projects/<answer>
```

The resulting `permissions.deny`, and the `AGENTS.md` lines, per project:

| Project | `permissions.deny` | `AGENTS.md` |
|---|---|---|
| opus | `Agent(coder-fleet:spec-editor-fable)`, `Agent(coder-fleet:tech-editor-fable)` | `Spec editor: opus`, `Tech editor: opus` |
| fable | `Agent(coder-fleet:spec-editor)`, `Agent(coder-fleet:tech-editor)` | `Spec editor: fable`, `Tech editor: fable` |
| neither | all four `Agent(coder-fleet:...)` rules | `Spec editor: neither`, `Tech editor: neither` |

The settings carry no `agent` key, which `/init` would add, so the `-p` session runs as a plain session rather than as the lead, whose board sweep would get in the way of a bare spawn test. The deny rules are the thing under test and are byte for byte what `editor-models.py` writes.

## The command

One run per project, from the project directory:

```
claude -p 'Use the Agent tool exactly five times, one call per message, never with run_in_background, in this order. Each call has the description "probe" and the prompt "Read nothing and write nothing. Reply only with your four-heading handoff, with the single bullet ready under Done." The subagent_type values, in order: coder-fleet:spec-editor, coder-fleet:spec-editor-fable, coder-fleet:tech-editor, coder-fleet:tech-editor-fable, spec-editor-fable. Carry on after any error. After the fifth call, stop.' \
    --plugin-dir <worktree>/claude/coder-fleet --setting-sources project,local --model haiku \
    --output-format stream-json --verbose --permission-mode dontAsk --allowedTools Agent --max-budget-usd 2.00
```

Every result below is read from the runtime's own events in the stream, not from the parent model's summary: the Agent `tool_result` (its `is_error` and text), the `tool_use_result` (`status`, `resolvedModel`), and the `task_started` and `task_updated` system events with the `message.model` of the subagent's own assistant turns. All three runs exited 0.

## The bare-name control CF-12.1 did not run

CF-12.1 admitted it never tried a bare name in a project with no deny rules. A fourth project, `control`, with the template `AGENTS.md` and `{}` settings, ran the same command shape with two spawns, `spec-editor-fable` then `spec-editor`:

```
Agent type 'spec-editor-fable' not found. Available agents: claude, coder-fleet:coder, coder-fleet:fleet-steward, coder-fleet:lead, coder-fleet:refuter, coder-fleet:researcher, coder-fleet:reviewer, coder-fleet:scout, coder-fleet:scripter, coder-fleet:spec-editor, coder-fleet:spec-editor-fable, coder-fleet:spec-writer, coder-fleet:tech-editor, coder-fleet:tech-editor-fable, coder-fleet:tech-writer, coder-fleet:ui-designer, Explore, general-purpose, Plan, statusline-setup
Agent type 'spec-editor' not found. Available agents: (the same list)
```

So a bare name reads "not found" whether or not a rule exists, which is the sentence criterion 5 puts in the README and the commands.

## A denied definition leaves the agent list

The "Available agents" list in the bare-name error differs by project. With no rules it names all four editors. With the opus rules it names `coder-fleet:spec-editor` and `coder-fleet:tech-editor` only, with the fable rules the two `-fable` definitions only, and with neither none of the four. The init event lists all four in every project, so the filtering is at spawn time, not at load.

A session sees the same filtered list. A run in the opus project and one in the control project asked the model, with no tool call, to list every `subagent_type` its Agent tool description offers:

```
claude -p 'Without calling any tool, list verbatim every subagent_type value your Agent tool description says is available, one per line, and nothing else.' \
    --plugin-dir <worktree>/claude/coder-fleet --setting-sources project,local --model haiku \
    --permission-mode dontAsk --allowedTools Agent --max-budget-usd 0.20
```

Its editor lines: `coder-fleet:spec-editor` and `coder-fleet:tech-editor` in the opus project; all four in the control. That is the model's report of its own tool description, one run each, and it agrees with the runtime's list above.

Consequence: `/kickoff`'s preflight 1 required all four editors to appear as agent types, so it would have failed in every project `/init` had just given deny rules. Preflight 1 now passes a denied editor's absence.

## Scope of this record

- Observed only under `--plugin-dir`, `--setting-sources project,local` and `--permission-mode dontAsk`, as CF-12.1's verdict was. A plugin installed from the marketplace, user settings in play, and interactive mode were not tried.
- The chosen spawns were backgrounded by the runtime. A foreground run of a chosen editor was not observed here.
- One run per answer. The denials quote the rule back by name, so a passing result by accident is unlikely, but nothing was repeated.
- A same-named agent under a project's own `.claude/agents/` is still untested, as CF-12.1 said.
