# CF-41: Ship prune-worktrees as a tested script

Status: approved by the human on 2026-09-27 with the recommended answer to every open question.

Board item: CF-41 (bug, Medium, To Do). Source: GitHub issue rzem-ai/coder-fleet#13, read as data. Route: coder. No dependency on another open item, and no board-fork change.

## Findings, with evidence

1. **Every step is prose, so every run is hand-rolled.** `claude/coder-fleet/commands/prune-worktrees.md:17-23` is the whole procedure: list (`:17`), three tests (`:9-13`), "`git worktree unlock <path>` ... then `git worktree remove <path>`. No `--force`, ever" (`:19`), "`git branch -d <branch>` - lowercase `-d`" (`:20`), `git worktree prune` (`:21`), the scratch sweep (`:22`) and the four-list report (`:23`). Nothing in the plugin implements any of it. The board item records the incident: a hand-rolled `grep -qx "$n"` read a scratch name beginning with `-` as options, the check that the entry was live failed, and live worktrees' scratch was deleted.

2. **Every encoded name starts with `-`.** The encoding is the path with `tr '/.' '--'` (`:22`), so an absolute path always encodes to a leading `-`. Live on this machine: `/private/tmp/claude-501/-Users-alex-Dev-Work-extensions-coder-fleet--claude-worktrees-agent-a44fdcc3322a23b72`. Any tool that takes the name as a pattern without `--` fails on every entry, not on an unlucky one.

3. **The prose's prefix test also passes other projects.** `:22` says "skip the entry unless its name starts with that prefix". A sibling repository whose path extends this one's passes that test. For example, a repo at `.../fathom/fathom-x` against this machine's repo `.../fathom/fathom` (`-Users-alex-Dev-Work-fathom-fathom`). Its worktree scratch then matches none of this repo's live worktrees and is deleted. The anchor has to be `<encoded-root>--claude-worktrees-`, not `<encoded-root>`.

4. **"Matches" is ambiguous, and exact equality deletes live scratch.** A session started in a subdirectory of a worktree gets its own entry, `<encoded-worktree>-<subdir>`. The listing shows the harness does this: `-Users-alex-Dev-Work-agents-angus` beside `-Users-alex-Dev-Work-agents-angus-workspace`. Worktree names are not only `agent-<hex>` either (`-Users-alex-Dev-Work-desktop-OpenLogi--claude-worktrees-feat-seed-app-navigation-profiles`).

5. **The encoding of characters other than `/` and `.` is unverified.** No entry under `~/.claude/projects/` or `/private/tmp/claude-501/` comes from a path with `_`, a space or another symbol (`ls ~/.claude/projects | grep -c _` is 0). If the harness replaces more characters than `tr '/.' '--'` does, a live worktree's encoded name would not match, and its scratch would be deleted.

6. **Where scripts live and how commands reach them.** `hooks/` holds only what `hooks.json` registers, and `hooks/README.md:3-15` describes it as exactly that set. Commands reach plugin files through `${CLAUDE_PLUGIN_ROOT}`: `board.md:11`, `kickoff.md:17` and `work.md:17` all call `${CLAUDE_PLUGIN_ROOT}/board/board.sh`. `claude/scripts/` sits outside the plugin, and "only this directory is copied at install" (`docs/fleet-design.md:177`), so a script the command calls must live under `claude/coder-fleet/`.

7. **The suite would not see a new plugin directory.** `check-all.sh:57-58` runs `bash -n` over `$PLUGIN_ROOT/hooks`, `$HARNESS_ROOT/scripts` and `$HARNESS_ROOT/evals` only. Contract tests are listed at `:68-77`. CI runs check-all on `ubuntu-latest` (`.github/workflows/checks.yml`) with git and bash, so this test runs in CI, unlike the board tests (CF-29).

8. **Closest model test.** `board-hook-contract.sh:655-660` builds a throwaway repo with a real linked worktree (`git init -q -b main`, per-repo `user.email`, `git worktree add -q`) under a `mktemp -d` root with `trap 'rm -rf "$TMP"' EXIT` (`:41-42`). `instruction-file-contract.sh:34-47` has the compact `check label cmd...` helper and the `-v` convention.

9. **Shell and path facts.** `/bin/bash` here is 3.2.57, so no `mapfile` and no associative arrays. On macOS, `mktemp -d` returns a path under `/var`, which is a symlink to `/private/var`, and git and the harness see real paths. Encoded names must therefore come from `pwd -P`.

10. **Callers.** `agents/lead.md:33` and `docs/fleet-design.md:51` point at `/coder-fleet:prune-worktrees` as the procedure. Neither needs to change. The design tree at `docs/fleet-design.md:180-186` lists plugin directories.

## Design decisions

1. **Script the whole command, not only step 6.** Every step was hand-rolled. The adoption checks and the `--force` ban are what make the command safe, and only a script can be contract-tested against real worktrees.

2. **Location: `claude/coder-fleet/scripts/prune-worktrees.sh`.** It is not a hook, so it does not go in `hooks/`. It must ship with the plugin, so it cannot go in `claude/scripts/`. A plain `scripts/` beside `hooks/` is the conventional name. The command calls `"${CLAUDE_PLUGIN_ROOT}/scripts/prune-worktrees.sh"`, with the placeholder double-quoted as `hooks.json` does. `bin/` is not recommended: whether the harness puts a plugin's `bin/` on PATH is unverified here.

3. **Interface.**
   - `prune-worktrees.sh [--dry-run]`, run from anywhere inside the repository.
   - The main checkout is resolved from `git rev-parse --path-format=absolute --git-common-dir`, so a run from inside a linked worktree still works on the main repository.
   - The scratch root is `CODER_FLEET_SCRATCH_ROOT`, else `/private/tmp/claude-$(id -u)` when `/private/tmp` exists, else `/tmp/claude-$(id -u)`.
   - Output is one tab-separated line per verdict, which the command turns into the four lists:
     - `removed <path> <branch|-> <head>`
     - `kept <path> <not-agent|current|locked|missing|dirty|unmerged>`
     - `scratch <name>`
     - `refused <path-or-branch> <first line of git's stderr>`
     - `sweep-skipped <reason>`
   - Under `--dry-run`, `removed` and `scratch` become `would-remove` and `would-delete-scratch`, and nothing is changed.
   - Exit 0 whenever it ran, refusals included. Exit 2 on a usage error or outside a git repository.

4. **Act by default, and `--dry-run` to preview.** This matches the issue ("a dry-run flag") and the command's current meaning. The lead runs it right after adoption, and a dry-run default would mean two calls every time. The protection comes from the checks, which the contract test now pins.

5. **Adoption, answered by git.**
   - **Agent path:** the path starts with `<main-root>/.claude/worktrees/`, trailing slash included, so `.claude/worktrees-x/` does not count.
   - **Clean:** `git -C <path> status --porcelain` is empty.
   - **Merged:** HEAD is an ancestor of `refs/heads/<default>` or of `refs/remotes/origin/<default>`, whichever exist. `<default>` comes from `git symbolic-ref -q refs/remotes/origin/HEAD` with `refs/remotes/origin/` stripped, else `main`. Either ref proves the commits exist outside the worktree.
   - **Current:** the worktree holding `$PWD` is kept as `current`.
   - **Unlocked:** a locked worktree is kept as `locked`, checked before missing, dirty and unmerged (decision 6).
   - **Present:** an unlocked, registered worktree whose directory is gone is kept as `missing`, and the prune drops its registration. A locked one keeps it, because `git worktree prune` skips locked entries.
   - All verdicts are collected before anything is removed.

6. **Removal.**
   - Changed by the lead on 2026-09-27 after review: the harness locks an agent worktree only while its agent runs, so the script never unlocks or removes a locked worktree and reports it as `kept <path> locked`, with no pid liveness check.
   - `git worktree remove <path>` for an unlocked worktree that passed all the checks. A refusal is reported and left as it is.
   - Then `git branch -d <branch>` for a worktree that had a branch, except the default branch.
   - Then one `git worktree prune`.
   - The script never contains `--force`, `-f` on a worktree command, or `-D`.

7. **Scratch sweep, conservative in every doubt.**
   - Runs after the prune, against a live list read afresh at that point.
   - Considers only real directories (`-d` and not `-L`) whose name starts with `<enc(main-root)>--claude-worktrees-`, where `enc` is `pwd -P` piped through `tr '/.' '--'`.
   - An entry is live when it equals `enc(wt)` or starts with `enc(wt)-` for any live linked worktree `wt`.
   - Only an entry that is not live is removed, with `rm -rf -- "$root/$name"`.
   - Names are compared with quoted `case` patterns and `[ = ]`, never grep. Any grep in the script takes `--` before its pattern.
   - If the main root or any live worktree path contains a character outside `[A-Za-z0-9/._-]`, the sweep is skipped and reported as `sweep-skipped encoding-unverified`, because the encoding of other characters is unverified (finding 5).

8. **The command keeps the contract and loses the procedure.** `prune-worktrees.md` keeps "What adopted means", becomes "run the script, then turn its lines into the four lists", passes `--dry-run` when the argument is `dry-run`, and says not to hand-roll any step. If the script is missing or exits with anything but 0, the command reports that, with the exit code and any lines printed, and stops. There is no manual fallback.

- **P02 dirty:** an untracked file in `.claude/worktrees/wt-dirty`. Kept with `dirty`, and the file still exists.
- **P03 unmerged:** a commit not in main. Kept with `unmerged`, and the branch still exists.
- **P04 not-agent:** a merged, clean worktree at `$TMP/elsewhere`, and one at `$R/.claude/worktrees-x/y`. Both kept with `not-agent`.
- **P05 detached:** a merged, detached worktree. Removed, and no `git branch` call reports a refusal.
- **P06 refused:** a merged, clean, unlocked worktree with a `modules` directory made in its admin directory (`git rev-parse --absolute-git-dir`), which is git's own submodule guard and refuses the remove before anything is deleted. Reported `refused`, the directory still exists, git still lists it, and its branch still exists. A read-only parent directory does not work here: git empties the worktree and drops its registration before it fails.
- **P07 main checkout:** the main checkout's HEAD, branch and working tree are unchanged.
- **P08 default branch:** a second small repo with `refs/remotes/origin/trunk` made by `git update-ref` and `origin/HEAD` pointed at it by `git symbolic-ref`. A worktree merged only into `origin/trunk` is removed, and one merged only into local `main` is kept `unmerged`.
- **P09 from inside a worktree:** run from inside a live worktree. The main root is resolved, and that worktree is kept `current`.

Scratch cases, under `$TMP/scratch`:
- **S01 stale:** `<enc R>--claude-worktrees-wt-gone` is deleted and reported.
- **S02 live:** `<enc R>--claude-worktrees-wt-dirty` is kept. The name starts with `-`, which is the class of the incident.
- **S03 live subdirectory:** `<enc R>--claude-worktrees-wt-dirty-claude-coder-fleet` is kept.
- **S04 main scratch:** `<enc R>` itself is kept.
- **S05 sibling repository:** `<enc R>-sibling--claude-worktrees-wt-x` is kept (finding 3).
- **S06 another project:** `-some-other-project--claude-worktrees-a` is kept.
- **S07 symlink:** a symlink named like a stale entry is kept, and its target is untouched.
- **S08 missing root:** a missing scratch root gives exit 0 and no `scratch` lines.
- **S09 unverified encoding:** a repo under `$TMP/with space` gives `sweep-skipped encoding-unverified`, and its stale-looking entry is kept.
- **S10 run order:** the sweep runs after the prune, so the scratch of P01's worktree, removed in the same run, is deleted in that run.

## Risks

- **The encoding is lossy.** `/x/a.b` and `/x/a-b` encode the same, so two repositories whose paths differ only there cannot be told apart. The anchored prefix makes this rare, and the reverse case, a stale entry kept because it prefix-matches a live worktree name such as `feat` against `feat-seed-...`, leaks scratch rather than deleting work.
- **Squash or rebase merges keep worktrees.** After one, HEAD is never an ancestor of the default branch, so the worktree is kept as `unmerged`. This is the safe direction, and the report names it.
- **The sandbox may block writes.** Whether the lead's Bash sandbox allows removing directories under `/private/tmp/claude-<uid>` is unverified. A refusal there shows up as a `refused` line, not silently.
- **A refusal while deleting is partial.** When `git worktree remove` fails on a permission error, git has already emptied the worktree and dropped its registration. The command tells the reader to look at the path before saying what is left.

## Open questions, each with a recommended answer

1. Script the whole command or only the sweep? **The whole command** (design decision 1).
2. Act by default or dry-run by default? **Act by default, with `--dry-run`** (design decision 4). The command passes `--dry-run` when the human gives `dry-run` as the argument.
3. Is ancestry of either the local default branch or `origin/<default>` enough? **Yes.** Either proves the commits exist outside the worktree, and neither needs a fetch.
4. Skip the sweep when a path has characters whose encoding is unverified? **Yes, and report it.** Deleting live scratch is the failure this item exists to end. If the human later confirms the harness's encoding, widen the allowed set in a follow-up.
5. `scripts/` or `bin/`? **`scripts/`.** `bin/` implies a PATH behaviour nobody has verified here.
