The human's rule, verbatim: "a refuter MUST NOT run for more than 20 minutes. please add the required changes to tell it to keep to 20 minutes, and a hard hook to kill it after 25". Not negotiable. This plan covers how.

## Findings that shape the plan

- **The scope hook cannot deny "every tool call" as registered.** `hooks.json:41-52` matches PreToolUse only on `Write|Edit|MultiEdit|NotebookEdit|Bash`. Read, Grep, Glob and the refuter's five memory MCP tools (`refuter.md:7`) never reach `enforce-agent-scope.sh`. To cover them, a matcher has to match every tool.
- **Widening the scope hook's matcher is the wrong way to do it.** Before the agent dispatch at `enforce-agent-scope.sh:414-417`, the hook validates the JSON, makes five jq calls and runs the quote and payload recovery (`:59-411`). A match-all matcher would put all of that on every Read, Grep and MCP call of every agent and the main session. The coupling is also bad. `docs/limits.md:23` documents command shapes that blow the 10-second timeout, and a hook that times out gives no decision, so the cap would disappear on exactly those calls. The plan therefore puts the cap in its own small hook, `hooks/agent-clock.sh`, registered with no matcher on PreToolUse and SubagentStart. `enforce-agent-scope.sh` stays unchanged. This departs from the brief's "in the PreToolUse scope hook", and open question 1 asks the human to confirm it. When parallel PreToolUse hooks disagree, deny wins: the 2.1.283 bundle folds decisions as `case"deny":vo="deny"` ahead of ask and allow.
- **`bound_at` cannot serve as the clock.** `lib/board.sh:103-120` writes it only when a board item is bound, because `board-subagent-start.sh:66-69` exits before binding when nothing is focused. It rewrites the file on every start, so a resume would reset it. It is ISO text, which macOS `date` cannot parse portably, and it is keyed by `session_id`. The clock needs its own record: keyed by agent id alone, epoch seconds, written once.
- **Resume re-fires SubagentStart for the same agent id.** The real `~/.local/state/coder-fleet/log/hooks.log` shows SubagentStart for `coder-fleet:spec-writer a12acd8657b8ff71c` six times and for `coder-fleet:coder a47642d26c23d56cf` three times. The same log shows `agent_type` arriving with the `coder-fleet:` prefix, although README item 16 says "bare". Both forms must be handled with `${agent_type##*:}`, as the scope hook already does at `:414`.
- **PreToolUse `updatedInput` works without a decision on 2.1.283, and the docs say the opposite.** code.claude.com/docs/en/hooks says "Without a decision, `updatedInput` is ignored". The installed bundle (`~/.local/share/claude/versions/2.1.283`) does this instead:
  - `if(Ee.updatedInput&&Ee.permissionBehavior===void 0)yield{type:"hookUpdatedInput",...}` is consumed as `case"hookUpdatedInput":ze=vo.updatedInput`, before the normal permission decision runs on `ze`.
  - The rewritten input is schema-checked (`n.inputSchema.safeParse`), and a failure is a deny.
  - So the in-flight gap can be closed by capping each refuter Bash call's `timeout` at the time left, and the rest of the permission flow still applies.
- **`"allow"` with `updatedInput` must not be used.** The docs say `"allow"` "bypasses both deny and ask rules in settings". That would wave refuter Bash calls past `Bash(curl *)`, `Bash(sudo *)` and the destructive-git denials in `claude/home/settings.json:3-41`. The rewrite therefore sends `updatedInput` with no `permissionDecision`, and a contract case pins that.
- **Bash timeout semantics on 2.1.283.** From the bundle:
  - The default is 120000 ms, or `BASH_DEFAULT_TIMEOUT_MS`.
  - The ceiling is `max(600000, BASH_MAX_TIMEOUT_MS)`. A requested timeout is clamped to the ceiling, not rejected, and there is no minimum.
  - Auto-backgrounding on timeout applies only when `isMainAgent`, so a subagent's command that hits its timeout is ended, not backgrounded. That is a reading of the bundle, not observed live.
  - Without the rewrite, a refuter blocked in a Bash call at 25:00 can run to 35:00 on defaults.
- **The SubagentStop gate still lets a capped refuter end.** After a deny the model gets a tool result and another turn, and needs no tool to write text.
  - A valid handoff gives exit 0 (`board-subagent-stop.sh:345-385`).
  - A malformed one gives exit 2 with the reasons (`:345-357`), and the fix is text-only again.
  - If the run stops on a trailing denied `tool_use` with no message, README item 16's table passes it unchecked (`:338-341`).
  - The gate never reads `stop_hook_active`, so a refuter that keeps writing malformed handoffs keeps being sent back. That was true before this change and stays text-only.
- **Cleaning up at SubagentStop would break the resume rule.** SubagentStop fires every time the subagent stops, including just before a SendMessage resume. Deleting the clock there means the resume's SubagentStart finds no file and starts a fresh 25 minutes. Clock files are never deleted, the same as `sessions/` (README:69): about 60 bytes per refuter spawn.
- **A timed-out refutation reads as clean in `review-round`.** `review-round.js:851-861` stops `refuted` only on `Blocker:` lines. A capped refuter whose unfinished work sits under Not done returns `stopped: "clean"`. This widens the existing gap at `docs/limits.md:47`. It is recorded here, not fixed (open question 6).
- **The scope contract harness sets no state directory.** `scope-hook-contract.sh:64-71` passes only `CLAUDE_PROJECT_DIR` and `CODER_FLEET_REPO`. Without a change, the new hook would write clock files into the real `~/.local/state`, so the contract must export `CODER_FLEET_STATE_DIR` under `$TMP`.
- **Bash 3.2 cannot be tested through the shebang.** Hooks run through `#!/usr/bin/env bash`, which is Homebrew bash 5.3 on this machine, while `/bin/bash` is 3.2.57. The new contract cases call the clock hook through `/bin/bash` explicitly, so on macOS they exercise 3.2.

Design section 4's refuter row (`fleet-design.md:37`) has no budget column; only the note at `:49` points at the looping skill's budget. No workflow prompt sets one (`review-round.js:829-844`). `claude/evals/refuter/` sets none.
- **Ports.** `opencode/coder-fleet/skill/looping/SKILL.md` is a vendored copy that already predates the budget section entirely. Nothing is written under `opencode/` or `codex/`.
- **Overlap with work in flight.**

## Design decisions in this plan

1. **One script for both events: `claude/coder-fleet/hooks/agent-clock.sh`.** It switches on `hook_event_name`. It does not source `lib/board.sh` (which would pull in `board.env`, and with it code execution), and it does not check `CODER_FLEET_BOARD` or the `disabled` file, so the clock runs whether or not the board does.
2. **A per-agent table with one row.** `clock_caps() { case "$1" in refuter) printf '1200 1500\n' ;; *) return 1 ;; esac; }` holds the advisory and hard caps in seconds. A table costs nothing over a special case and keeps both numbers in one place. No other agent is added. The human's rule names the refuter, and a coder phase legitimately runs long in a worktree with its own round budget.
3. **State.** The clock lives at `$CODER_FLEET_STATE_DIR/clocks/<agent_id>`, with the directory resolved as `CODER_FLEET_STATE_DIR`, else `XDG_STATE_HOME/coder-fleet`, else `~/.local/state/coder-fleet`. The id is sanitised with `tr -c 'A-Za-z0-9._-' '_'` as `lib/board.sh:106` does. The directory is 0700 and the file 0600. The file holds three lines: `started_at=<epoch seconds>`, `started_iso=<UTC ISO>` (for people reading it; the hook never reads it) and `agent_type=<type>`. It is keyed by agent id alone because agent ids are unique, and because keying by session would lose the clock if a resumed session carried a different session id.
4. **Clock source.** `date +%s` on the same machine at both ends. It is portable across BSD and GNU and has no parsing step. `$EPOCHSECONDS` is not used because bash 3.2 lacks it. Negative elapsed time, from a clock stepped back, counts as 0. Machine sleep counts as elapsed time: the rule is wall-clock.
5. **Create-if-absent, atomically.** `( set -C; printf ... > "$file" ) 2>/dev/null` uses noclobber, which is O_EXCL. A second SubagentStart for the same id (a resume) finds the file, leaves it alone and logs that the first start stands.
6. **Missing state fails open, then starts the clock.** If PreToolUse finds no file for a capped agent, it creates one with "now", allows the call and logs the late start. The alternatives are worse:
   - Failing closed would deny every call from the first, killing a whole run over a hook that timed out or an unwritable directory. The scope hook's documented contract is to fail open.
   - Failing open without recording would leave the run uncapped for good.
   - The late start costs only the model's first-turn thinking time.

   Other failures fail open as well, each with a log line: a file that exists but will not parse, an unwritable directory, or a missing jq.
7. **Deny at or after the hard cap.** `elapsed >= 1500` denies every tool call, in the same JSON shape as `enforce-agent-scope.sh:25-37`. The reason quotes the new invariant verbatim, following the README's "What breaks them" rule (`:350`):

   `refuter invariant: "Never run past 20 minutes of wall-clock from your spawn." This run has been going <M> minutes, past the 25-minute hard cap, so this call and every later one is denied - do not retry it or try another tool. End now with your four-heading handoff from what you already have: what you ran and what died under Done, and every claim or mutation you did not finish under Not done, named, so a fresh refuter can start there.`

   Minutes only: formatting a stored epoch as a time of day needs `date -r` on BSD and `date -d @` on GNU.
8. **Bash timeout trim under the cap.** For a capped agent's Bash call:
   - `remaining_ms = (1500 - elapsed) * 1000`.
   - `requested` is `tool_input.timeout` if it is a positive integer, else `BASH_DEFAULT_TIMEOUT_MS` if that is a positive integer, else 120000.
   - If `remaining_ms < requested`, emit `{hookSpecificOutput:{hookEventName:"PreToolUse",updatedInput:(.tool_input + {timeout:N})}}` with `N = max(remaining_ms, 5000)`. There is no `permissionDecision`, and every other input field is preserved because the jq merges into the original `tool_input`.
   - Otherwise emit nothing.

   The call only changes when the cap would bite. The true ceiling becomes 25:05 plus kill latency.
9. **A fast path for the main session.** If the raw input does not contain `"agent_id"`, the hook exits 0 before jq runs. Otherwise it makes one jq call, joining the fields with `\u001f` and splitting them with `IFS=$'\x1f' read -r`. A tab separator would collapse empty fields, because tab is IFS whitespace.
10. **Logging.** Each log line goes to stderr and to `$STATE_DIR/log/hooks.log`, under the tag `[AgentClock]`.
11. **Rejected mechanisms.**
    - A watchdog process that kills children: a subagent is not its own process, and its Bash children cannot be told apart reliably.
    - `continue:false` from PreToolUse: the bundle has `preventContinuation`, but it would end the run with no handoff. With tools denied, the refuter can only write text anyway. See open question 8.
    - `"allow"` plus `updatedInput`: it bypasses the settings deny rules.

## Agent routing

Every phase goes to `coder`. `lead.md` step 2 (`:30`) routes hook code and any phase of a multi-phase plan there; `scripter` is excluded by the multi-phase rule, and `tech-writer` cannot reach `claude/`.

- Phases 1-4 share one `coder` run, one worktree cut from `origin/main`, one branch (`cf-23-refuter-clock`) and one commit per phase.
- Before the spawn, the lead calls `task_focus CF-23`.
- After the run: `review-round` over the branch, with `fix: true` if it comes back with blocking findings. Then `refuter` against the change if the review lists the gates under Unverified. The installed plugin predates the cap, so that refuter's brief states the 20-minute rule explicitly.

Known constraints for the coder brief:

- The worktree guard refuses `${VAR:-default}`, relative script paths, a pipe after `bash <script>`, `&&` chains that invoke bash, and PATH overrides on the command line.
- So file content is written with Write and Edit, never a heredoc through Bash.
- Every command names scripts by absolute worktree path. Below, `<wt>` stands for that path.
- The coder has neither the Skill tool nor `migration-checklist` preloaded, so it reads `claude/coder-fleet/skills/migration-checklist/SKILL.md` as a file.

## Risks

- **Passthrough `updatedInput` is undocumented.** A CLI that follows the docs drops the trim silently. The deny still holds, and the contract pins the hook's output, not the runtime's use of it. Mitigations: README item 20's re-derivation, the limits entry and the live probe.
- **A match-all PreToolUse runs a process on every tool call in every session.** Main-session calls exit before jq; subagent calls pay one bash start and one jq. The hook's timeout is 5 seconds and it fails open.
- **Wall-clock includes machine sleep.** A refuter on a laptop that slept is denied when it wakes. This is intended, and the limits entry says so.
- **Bash 3.2.** The contract drives the clock hook through `/bin/bash` so macOS exercises 3.2. On Linux CI, `/bin/bash` is 5.x, so a 3.2-only regression is caught only locally.
- **Timing flakiness.** Every boundary case keeps at least a 10-second margin, and the trim assertions are ranges, not exact values, except the floor.
- **The contract would write real state without the export.** `CODER_FLEET_STATE_DIR` must be exported before the first clock case, or the tests write into `~/.local/state`. The deny and resume cases confirm the export took, since they read clock files the contract wrote under `$TMP`; `clock-main-session` cannot, because the hook writes nothing for it either way.
- **A refuter spawned for this PR's own verification runs on the installed plugin**, which has no cap. Its brief states the 20-minute rule by message, as was done for the CF-9 and CF-12.2 refuters.
- **The instruction-file contract** fails on any new mention of the other instruction-file name anywhere in the repo, this plan included, and on any change to the pinned design lines.
- **Rebase conflicts with CF-9 and CF-12.2**, as listed. Both are textual, not semantic.
