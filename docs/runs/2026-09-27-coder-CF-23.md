# A wall-clock cap for the refuter, in a hook of its own

2026-09-27, coder, CF-23: built `agent-clock.sh`, which denies every refuter tool call past 25 minutes and trims its Bash timeouts under the cap, told the refuter and the lead about the 20-minute round, and documented the lot.

## What the run was

The human's rule is that a refuter must not run past 20 minutes and that a hook stops it at 25. The approved plan put the cap in a new hook, `claude/coder-fleet/hooks/agent-clock.sh`, registered with no matcher on `SubagentStart` and `PreToolUse`, rather than in `enforce-agent-scope.sh`, whose matcher only sees five tools. The run was four phases on one branch: the hook test-first, the refuter body and the `looping` skill, the docs, and a 0.27.0 bump. The Bash trim rests on runtime behaviour the documentation contradicts: `updatedInput` sent without a `permissionDecision` is honoured by the 2.1.283 bundle, not ignored as the docs say.

## What was tried and abandoned

**`set -o errtrace` in the hook.** I added it so that the ERR trap, which logs and exits 0, would also fire inside functions. The first green run failed two cases, `clock-start-others` and `clock-bash-other-agent`: a coder got a clock file and had its Bash timeout trimmed. The trap had been inherited into `caps="$(clock_caps "$agent")" || exit 0`, fired on the table's `return 1` inside the substitution, and exited the subshell with status 0, so the `|| exit 0` never ran and an uncapped agent carried on with empty caps. I dropped errtrace, which the plan and the scope hook never used, and made the lookup test its output (`[ -n "$caps" ] || exit 0`) rather than its status, so a trap can never turn "not capped" into "capped".

**The first red run.** My `clock_event` helper read `$4` under `set -u`, and `SubagentStart` events pass three arguments, so the start cases failed for a harness reason rather than a missing hook. A red run that fails for the wrong reason proves nothing, so I fixed the helper and ran red again: 20 failed, 344 passed, and every failure was a deny, rewrite, record, resume, lazy-start, registration or executable case.

**The floor case at 1498 seconds, as the plan's table said.** Any floor case sits within five seconds of the deny, because the floor only bites when fewer than 5000 ms are left. At 1498 there is one second of slack before the case flips to a deny; at 1496 there are three, and the timeout still floors at 5000 for any elapsed from 1496 to 1499. I used 1496. It is the plan's own margin principle applied, but it is a departure from the table and the reviewer should know.

**`grep -q` at the end of a pipeline under `pipefail`.** It can exit early and SIGPIPE the grep before it, which `pipefail` reports as a failure. The corrupt-file case uses `grep ... >/dev/null` instead.

**The scratch-directory clause in the looping skill.** Card criterion 6 arrived mid-run with the human's approval. It went into `refuter.md` step 2, folded into the existing line so the body stayed at 48. I left it out of the skill: its budget paragraph is about time, and the clause would have read as bolted on.

## What the constraint turned out to be

A fail-open hook has one dangerous failure direction, and it is not the one the deny cases test. If the clock hook breaks, the refuter is uncapped, and the log says so. If it over-reaches, every coder, reviewer and main-session call pays for it, silently: a trimmed timeout looks like a slow test. The allow cases that pass with or without the hook (`clock-others-unaffected-*`, `clock-main-session`, `clock-bash-other-agent`, `clock-start-others`) looked like padding when the plan listed them. They were the ones that caught the only real bug in the run.

The other constraint is that the contract pins what the hook prints, never what the runtime does with it. Whether 2.1.283 really applies a decision-less `updatedInput`, and whether a subagent's timed-out Bash call is ended rather than backgrounded, are readings of a minified bundle. Nothing here proves them live.

## What to do differently

Check trap inheritance before adding `errtrace` to any hook in this repo; plain `set -euo pipefail` with an ERR trap at top level is the convention for a reason. Run the post-merge probe in hooks README item 20 before trusting the trim, and after any CLI upgrade run its `strings` search first: if `permissionBehavior===void 0` is gone, the trim is dead and only the deny remains. The next person extending the table to another agent should add its row to both `clock_caps` and `clock_invariant`, and copy the over-reach cases for the agents that stay uncapped.
