# One gate, two callers: the spec-editor pair and the challenge gate

2026-10-07, coder, CF-12.3. Built the fleet's first bounded Fable subagent pair and the first check shared between a lead instruction and a workflow.

## What the run was

CF-12.3 added `spec-editor` and `spec-editor-fable`, generated from `claude/agent-pairs/spec-editor.md`, and the challenge gate that stops building while a must-resolve challenge is open. The gate had to run from two places that share nothing at runtime: an instruction in `lead.md` step 3, read by a model in the main session, and a lane in `spec-to-card.js`, a script whose lanes are separate agents. The card's constraint was one copy of the logic.

## What was tried and abandoned

A `challenge-gate` skill, which the dropped CF-12.3 plan had chosen. A skill only preloads text into an agent; a workflow cannot load one, and `lead.md` has no room for a procedure. The gate became `claude/coder-fleet/scripts/challenge-gate.py`, beside `prune-worktrees.sh`, which is where the plugin already keeps scripts that commands run.

A shell gate. The decision is a few regexes, but the close must leave every other line byte-identical: CRLF files, a missing final newline and undecodable bytes all have to survive. Bash and awk can do it, but each of those cases becomes its own trap. Python with `splitlines(keepends=True)` and `surrogateescape` made byte identity the default, and the hooks already depend on `python3 -I`.

Hand-typed gate output in the workflow tests. The first draft stubbed the lane with lines written in `workflow-logic.mjs`, which is a second copy of the output format: drift between it and the script would pass every test. The tests now run the real script, `check` on fixture specs and `run` in a throwaway repository, and hand its stdout to the stubbed lane.

A copied eval for the Fable twin. `roster-contract.sh` wants an eval directory per agent, and two copies of four prompts would drift. `claude/evals/spec-editor-fable/` symlinks `prompts`, `rubric.md` and `checks.sh` to `spec-editor/` and keeps its own baseline. Then `find spec-editor-fable/prompts -name '*.md' -type f`, the runner's way of listing prompts, found 0 files, while `roster-contract.sh`, which counts with `ls`, would have passed: `find` does not descend into a starting directory that is a symlink. With a trailing slash it found 4, and `run.sh` now passes one.

`Write` for the editor. The spec's supplied tools line has it, but the editor never creates a file, and `Write` replaces a whole spec in one call, which is the easiest way to break the byte-identical rule. Both bodies grant `Edit` only and list `Write` under `disallowedTools`.

## What the constraint turned out to be

Finding the script, not deciding the verdict. The docs (`plugins-reference`, "Where each variable resolves") say `${CLAUDE_PLUGIN_ROOT}` is substituted inline in agent, skill and command Markdown but is never in the Bash tool's environment. So `lead.md` names `"${CLAUDE_PLUGIN_ROOT}/scripts/challenge-gate.py"` literally, while the workflow's lane uses the cache search `BOARD` already uses. Two spellings of the path, one file.

The second was what the closed marker's sha must name. If the human resolved challenges and has not committed, HEAD does not hold the section that passed. `run` therefore commits the spec alone first when it differs from HEAD, then closes. Both commits use `--only -- <spec>`, so a dirty or staged file elsewhere never rides along; the contract proves that with a modified file and a staged one.

Negative tests lied more than once. With no script present, six gate cases passed: Python exits 2 on a missing file, which read as a refusal. In the workflow tests, the marker case passed because the stub card had no tick count, and an ordering case passed because a missing lane's index is -1. Each was tightened to need the specific exit code, message or index before it could pass.

## What to do differently

Run every new contract once before the code exists and read which cases pass, not only the count. Look up a variable's scope in the docs before writing an instruction that depends on it. For a pair's eval, check what the runner actually lists (`run.sh <agent> --dry-run`), not only what the roster counts. The early-handoff instruction is still untested on Fable, and the effort sweep and live evals for both definitions are still to run.
