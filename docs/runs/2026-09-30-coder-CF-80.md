# Binding a workflow run to its launch item at SubagentStop

2026-09-30, coder, CF-80: moved a workflow run's comments and Blockers onto the item its first lane started on, deciding the item at the stop because the start cannot see the run.

## What the run was

A review-round launched on one item and a refocus minutes later sent its late refuter's handoff to the new card, because `board-subagent-start.sh` binds each lane from the focus when that lane starts. The human had already chosen to resolve the run's item at `SubagentStop`, after the lead showed that `SubagentStart` names no run. The run built that on top of the unmerged CF-48 branch, in `board-subagent-stop.sh` and four new helpers in `hooks/lib/board.sh`, with eight `wf-` contract cases.

## What was tried and abandoned

Ordering lanes by `bound_at` from their start records. It is the obvious field and it is already there, but it counts whole seconds, and a workflow launches parallel lanes inside one second. On a tie the choice falls to something arbitrary, and if that something is the name, a lane started after a refocus can win. It was dropped before any code was written, in favour of the record file's modification time, which the start hook sets once and nothing rewrites.

Trusting the record read after losing the write race. The first version of the stop, on `state_record_run` returning 3 (another stop got there first), re-read the record and set the item from that read. If the read failed, the item came out empty, and the lane commented nowhere. The never-read-the-record mutation exposed this: it failed `wf-late-lane-comments-on-launch-item`, because the second stop lost the write, could not read, and dropped the item. The race loser now falls back to the item it computed itself, which is the same deterministic answer the winner wrote.

Writing the run record with `set -C`, as `state_bind_agent` does. `O_EXCL` stops two writers, but a racing reader can open the file between its creation and its contents and read an empty `page_id`, which in this design means "comment nowhere". That is a silent wrong answer, not a soft failure. This too was rejected on paper: the record is written to a private temp file and hard-linked into place, so it appears whole or not at all, and `ln` refuses an existing name.

Recomputing the item at every stop and skipping the record. Two stops would agree if they saw the same lanes, but a later stop sees a different run directory, since lanes keep appearing and lanes whose record was never written drop out. The card asks for one answer per run, so the first stop's answer is kept and `wf-record-read-by-later-stop` removes lane 1's transcript and record between stops to prove the second stop never recomputes.

## What the constraint turned out to be

Only `SubagentStop` sees the run. The lead's capture had already established that, and the brief carried it. The surprise was a constraint the brief did not mention: `hooks.json` registers the stop hook only for the eleven fleet names, so an untyped lane (`agent_type: workflow-subagent`) never stops through it. Untyped lanes still write start records, because the start hook has no matcher, and that is enough: the earliest lane of a review-round is usually an untyped git lane, and its start record decides the item for the typed refuter that stops much later. "Typed and untyped lanes alike" therefore holds for resolution but not for commenting, and untyped lanes never had a handoff to comment anyway.

The code came out as a branch in front of the old lookup: a transcript path with a `workflows/wf_<run>` segment goes to the run record, then to the earliest start record among the run directory's `agent-*.jsonl` plus the stopping agent, then to nothing. Direct spawns take the old path unchanged, the `CODER_FLEET_BOARD_PAGE_ID` fallback included.

## What to do differently

Name test ids against the property under test. The lanes here are `wz1` (started first) and `wa2` (started second), so they sort against their start order, and the mutation that swapped `ls -1tr` for `ls -1` failed seven cases. Ids that sorted in start order would have passed a resolver that ignored time.

Before relying on it, check that the `agent-<id>.jsonl` filename's id is exactly the event's `agent_id`. The card's capture suggests it is, since fathom's state file `agents/aeb7ad765648cbebc` matches the pattern, but no live run has put a real run directory through this code. A mismatch would drop every lane but the stopping one from the candidates, and each lane would fall back to its own binding without any error.

The board suite needs `bun install --frozen-lockfile` in a fresh worktree. Without it, 115 load errors look like a broken package.
