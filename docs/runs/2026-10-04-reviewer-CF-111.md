# Reviewing a deliberate security downgrade: CF-111 disabled agents

2026-10-04, reviewer, CF-111. A read-only review of the branch that lets a project switch off fleet agents, the refuter first.

## What the run was

The refuter is the fleet's only gate that mutates code to prove the tests can fail, and review-round forced it on auth and secrets paths. CF-111 lets `.claude/coder-fleet.json` turn it off, by the human's choice. The question was not whether the downgrade should exist but whether anything other than the intended file could trigger it.

## What was tried and abandoned

I started by probing the jq and JS readers directly with crafted strings (BOM, NBSP, NEL, embedded newline, multi-value streams). The reviewer's scope hook refused both `jq` and `node` as non-reading commands, so those probes turned into reasoning from known jq and ECMAScript behaviour plus explicit Unverified items for the refuter. Next time, list the probe fixtures up front so the refuter can run them.

I also looked hard at the six unused-variable diagnostics as a sign of disconnected approval logic. Reading lines 1494-1663 showed all six feed the top-level `return`. The diagnostics come from an editor that cannot model a top-level return in a workflow script, which is a pattern older than this branch.

## What the constraint turned out to be

The normalisation rules were careful and the core-agent rejection held in both readers. The weak point was where the file is read from. Both the hook and the pin lane read a working tree: the call's cwd or the workflow's checkout. Neither reads a committed revision, so the branch under review can carry the config that exempts it. The second surprise was jq's stream semantics: a file holding two JSON values is honoured by the shell reader using only the first, while JSON.parse rejects it.

## What to do differently

For any config that relaxes a gate, ask first which revision it is read from, before looking at how it is parsed. Parity tests between two parsers need adversarial fixtures (non-ASCII whitespace, multiple values, embedded newlines), not just a list of well-formed and obviously broken files.
