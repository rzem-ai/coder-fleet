# Known limits

What the fleet deliberately does not enforce or cover. Each item is a gap that was looked at and left, with the reason, so a deliberate gap is not mistaken for an oversight. Anything here that becomes a rule, a hook or a test leaves this file the same day.

## The board hooks

**The route to Done depends on a Claude Code gate the fleet does not own.** `TaskCompleted` fires only when a task is completed with `TaskUpdate`, and Claude Code 2.1.283 offers the task tools to current models only when `CLAUDE_CODE_ENABLE_TODO_TOOLS` is set. The fleet sets it at project and user scope, but a later CLI can rename the variable or change the default. `/kickoff` checks that the lead has `TaskUpdate`, which turns such a change into a named failure rather than a board where nothing reaches Done again.

**Failure and cancellation never reach Blocked.** `SubagentStop` carries no `status` field, so `board-subagent-stop.sh` cannot detect a failed or cancelled run. The hook reads no status; the dormant branch was removed in v0.25.1. A `Blocker:` line in the handoff routes to Blocked by human, and `TaskCompleted` is the only writer of Blocked. `agent_transcript_path` is present on every `SubagentStop` event and the hook already walks it to tell a schema spawn from a silent run, so what is missing is narrower than a new reader: teaching the existing one to recognise a failed or cancelled run.

**A first start is bound per checkout, not per agent.** The hooks read the checkout's `.boards/.focus` at an agent's first start, so every fresh spawn in a focused checkout belongs to that item. A resume is the exception: it keeps the record its first start wrote, so refocusing between a spawn and its resume no longer moves it. Per-agent binding at the first start needs a supported correlation between the Agent tool's invocation and the subagent identity in the event, and it must not be done with a shared "latest prompt" file: two agents spawned together would race for the same line. `SubagentStart` does carry `agent_id`, `cwd` and `prompt_id`, which is more to work with than the hooks currently use.

**The transcript reader fails open.** `board-subagent-stop.sh` consults `agent_transcript_path` to tell a schema-spawned run from one that produced nothing, and a transcript it cannot read - missing, unreadable, oversized, unparseable - passes with a log line rather than blocking. Deliberate: deadlocking a subagent is worse than a rare silent pass.

**The binary knows the human queue only as "Blocked by human".** The Actions for Human settle, which clears the section when a card leaves the human queue, matches the constant `Blocked by human` in the board binary, ignoring case and spaces, and never reads `board.env`. A `BOARD_COL_BLOCKED_HUMAN` override renames the column the hooks write and the one `SubagentStart`'s hold rule reads, but not the one the binary clears on leaving, so on a board whose queue is spelled otherwise, a card leaving it keeps its actions until it enters Done. Every template and this repository use the default name, and a config key would be a second place to keep in step with `board.env`; an item gets filed if an override is ever used. The human clears the section only by moving the card.

## The scope hook

**It is not a containment boundary.** `enforce-agent-scope.sh` reads shell text, and a shell does not. A program run through Bash writes wherever the process can, and no shell-level check sees inside it. The sandbox in `claude/home/settings.json` is a credential boundary, not a role boundary - its `denyWrite` covers `~/.ssh` and friends, not other repositories. Unattended steward runs need filesystem permissions before they are safe, and the steward is the agent this matters most for. Every entry below is one consequence of that; finding one hole is not evidence there are no others.

**`strip_quoted` pairs quotes naively in the general segmenter.** `echo "say \"x" ; git commit -m x ; echo "the end"` is allowed for `scout`, even though a real shell runs the commit as its own command: the escaped quote inside the first span shifts the parity, and the later quoted `"the end"` gives the naive pairing something to close against, erasing everything between, including the commit. The escape-aware stripper only reaches the interpreter-payload regex; the general command-segmentation path that every `enforce_*` function walks still uses the naive one.

**The 8192-byte scan bound truncates.** `echo <9000 bytes> ; git commit -m x` is allowed, with a log line naming how far over the bound the command was. Without the bound a long enough command blew the hook's 10-second timeout, which renders no decision at all and takes every role's guard down silently with no log. A narrow logged bypass is the trade for an absolute silent one.

**The 16-segment bound truncates the same way, and it is the tighter of the two.** `echo a ; ` sixteen times in front of `git commit -m x` is allowed for `refuter`, with a log line saying how many segments were dropped. Sixteen is generous against real work - the coder-fleet repo's own scope-hook corpus tops out at four segments - and the bound exists because bytes were never the cost: 200 chained `git log` steps is 2000 bytes, a quarter of the byte bound, and measures well past the 10-second timeout without it.

**Per-segment word count is unbounded.** `A=1 ` five hundred times in front of `git log` is 2007 bytes and one segment, and measures about 17 seconds against a 10-second timeout. `command_words` spawns two processes per leading assignment or wrapper word and nothing caps how many it walks. The fix is either a third bound or the single-pass rewrite that replaces all three.

**Variable expansion, `eval`, heredocs and other languages' inline-code flags are unreachable.** Any parser reading unexpanded text cannot see them. `python3 -c "import os; os.system('git commit -m x')"`, `node -e` and `perl -e` are all allowed; they are `eval` wearing a different name. The hook recovers payloads from `bash -c` and its four sibling shells only, and its own comment says so.

**Command substitution is unchecked for three roles.** `$(git commit -m x)` and the backtick form are allowed for `refuter`, `coder` and `ui-designer`, because only `fleet-steward`, `scout` and `reviewer` check for substitution. The leading-token strip that closes `{ git commit -m x; }`, `( git commit -m x )`, `! git commit -m x`, `>/tmp/out git commit -m x`, `timeout 5 git commit -m x` and the body of an `if`, `for` or `while` cannot reach a substitution, because the word has no leading token to remove. `script -q /dev/null git commit -m x` stays open on purpose: `script` puts its typescript file between itself and the command, so listing it as a wrapper would close nothing, and `script cat` would then read as `cat` while actually creating a file called `cat` - the same asymmetry that keeps `sudo` off the wrapper list.

**The refuter's "Never write inside the project" is not enforced against Bash.** `lib/check-write-scope.py` only ever sees `Write`, `Edit`, `MultiEdit` and `NotebookEdit`, so `echo mutated > claude/coder-fleet/agents/coder.md`, `cp /tmp/x claude/coder-fleet/workflows/review-round.js` and `rm -rf claude/coder-fleet` are every one of them allowed. `enforce_fleet_steward` resolves and checks redirection targets for an equivalent rule, so the pattern exists in the same file, and applying it here would still only reach redirections rather than `cp` or `rm` - which is why it is a design question rather than a missing line.

**An `agentType`-less lane is governed by nothing.** The `SubagentStop` matcher skips it and every branch of `enforce-agent-scope.sh` keys on an agent name, so "read-only git only" in a lane prompt is an instruction to a model, not a boundary. The four mechanical lanes in the workflows have always been in that position - they run the project's test suite - and `review-round`'s two git lanes are in it too. Widening `scout`'s or `reviewer`'s allowlist instead would weaken a role boundary for every run rather than for the one workflow that needs `worktree`, `merge-base` and `rev-parse`. A probe spawn that falls back to a non-fleet agent type can run `git commit --allow-empty` in the main checkout and it lands with no refusal.

**A named, non-isolated spawn escapes the fleet entirely, and it is the likeliest shape of a trample.** Spawning a fleet agent with a `name` and no `isolation` puts it on the teammate path, where the hook events carry the name as `agent_type`: `enforce-agent-scope.sh` then allows everything, because no agent type it knows means the main session; the `SubagentStop` matcher never matches; no worktree is cut. A named `coder` commits straight to main with no refusal anywhere. A named read-only agent loses its whole output instead: idle notifications arrive in place of a result, the stop gate's exit 2 has nowhere to deliver, and the run looks like a success with a formatting hiccup. So a named spawn loses whichever half of the contract the role depends on, and neither failure is loud. A named refuter loses the time cap as well, because `agent-clock.sh` keys on the same agent type. The refusal branch of the worktree guard may be unreachable from a real typed spawn - a typed `coder` always gets a worktree, and only the ungoverned path ends up in the main checkout - which makes the teammate path the whole risk. Until the hook can key on something a teammate cannot rename, the rule is operational: never name a fleet spawn, and treat a teammate running a fleet body as ungoverned. The lead's body says so.

## The refuter's time cap

**The cap stops tools, not the model.** Past 25 minutes `agent-clock.sh` denies every tool call, but a turn that writes only text needs no tool, so text-only turns after the cap - including the re-emits `SubagentStop` asks for when a handoff is malformed - are bounded by the model alone.

**The in-flight Bash trim depends on undocumented behaviour.** Sending `updatedInput` with no permission decision is honoured by the 2.1.283 bundle and contradicted by the documentation (hooks README, item 20). If a later CLI follows the docs, the trim silently stops and the gap reopens to 25 minutes plus one command, up to the runtime's Bash ceiling, 10 minutes by default. The deny still holds.

**`run_in_background` is outside any timeout.** A backgrounded command can outlive the run. The run itself should not be held open, since `SubagentStop` carries `background_tasks`, but that is unobserved live.

**Missing state starts the clock late, and a corrupt file uncaps the run.** Both allow the call with a log line. A refuter that deletes its own clock file restarts its clock at the next tool call: a speed bump, not a boundary.

**Nothing counts mutants.** At most eight mutants a round is an instruction in the refuter's body, the `looping` skill, the lead's brief and `review-round`'s refuter prompt, and no hook or workflow counts them. A refuter that runs a ninth is stopped only by the 20-minute round and the 25-minute deny, which bind first on any suite slower than about 100 seconds run one after another. Counting would mean parsing mutations out of Bash calls, and the time cap already bounds the spend.

**A refuter run as the main agent is uncapped.** With `--agent refuter` the events carry no `agent_id`, and the hook exits before it reads anything.

**Wall-clock includes machine sleep.** A refuter on a laptop that slept is denied when it wakes. That is intended: the rule is wall-clock.

## Never run against a live Claude

**The refuter.** Its permissions are pinned by 85 deterministic checks in the scope hook suite and its evals exist, but no stubbed suite can show whether an agent given that body actually refutes rather than reviews. `claude/evals/refuter/` probes both directions - a change with a genuinely vacuous test, and a change with nothing wrong where inventing a finding is the failure - and until it runs, the role is a design rather than a capability.

**`fix: true` in `review-round`.** Every branch is covered by deterministic tests that stub the model out, which is exactly the coverage that can hide a gate bug for a fortnight. What those cannot prove: that the git lanes report `isMain` correctly off `git worktree list --porcelain`, that `coder` follows the `git switch` instruction, and that `parallel()` returns lanes in a shape the tests-lane lookup finds. The lookup is by name rather than by position for that reason.

**`refute: true` and the refutation stage.** Same coverage, same gap. What the stubs cannot prove: that a refuter asked to attack a change copies out of the project rather than mutating the tree under test, and that `survivorsOf` on a real refutation finds the `survived:` Done bullets the way the fixtures say it will.

**Worktree isolation for a workflow-spawned `coder`.** An Agent-tool `coder` spawned with the fleet type gets a locked linked worktree and its commit stays on the per-agent branch, with or without an explicit `isolation` argument, because the harness honours the definition's frontmatter. `review-round` cuts its own worktrees through `worktree.baseRef`, which is a separate mechanism, and that path has not been run live in a repository with a remote. `baseRef` defaults to `fresh`, which branches from `origin/<default-branch>`, so a repository with no remote cannot cut one at all. The cost is load-bearing: `enforce_coder` refuses a writing git command outside a linked worktree (`claude/coder-fleet/hooks/README.md` item 18), so if isolation does not hold, `coder` stops rather than committing to a shared checkout. That is the intended failure, and it means loop work built on `fix: true` may not run at all until this is settled.

**The refuter's time cap, end to end.** The contract pins what `agent-clock.sh` outputs, not what the runtime does with it: that a live refuter is denied at 25 minutes, writes its handoff after the deny, and has a long Bash call ended at the trimmed timeout. The post-merge probe in hooks README item 20 covers it until it runs.

## Refutation checks that do not exist

**Nothing checks that a refutation contains mutation evidence.** `review-round` stops on a `survived:` Done bullet, on a `Blocker:` line and on an empty refutation, and treats everything else as unbroken. The survivor transport is itself unproven: no live refuter has yet been seen to write a `survived:` bullet, and the reader fails closed: any Done bullet that mentions surviving, a bare `survived:` key included, stops the round unless the whole bullet is one of a small set of strict nothing-survived forms. What it cannot see, and so fails open on, is a survivor described without the stem ("lived", "not killed", "not noticed"), look-alike or invisible characters inside the word, list markers other than `- `, and a clean-looking `survived: none` followed by a separate bullet that names a survivor. It never looks at whether the Done section says anything was mutated. A refutation whose only Done bullet is "I read the diff and it looks fine to me" returns `stopped: "clean"` and `approved: true`, which is the exact failure the role exists to prevent, arriving through the gate rather than around it. The check is deferred on purpose: it would have to pin a workflow decision to a new obligation on the refuter's Done-bullet wording, and a format obligation invented and depended on in one commit is how format obligations decay. The `survived:` bullet is not that case: survivors were already a parsed obligation, moved from Decisions needed to Done rather than invented, and the bullet rides the keyed Done bullets `fixHints` already depends on. The evidence check gets built once there is a real refutation handoff to parse, which needs the live runs above. The time cap widens the gap: a refutation stopped at 25 minutes, with its unfinished mutations under Not done, carries no `Blocker:` line and is read as clean too.

**The sensitive override covers authentication and secrets only.** Under `fix: true`, `review-round` spawns a refuter despite `refute: false` when a round's changed files match `SENSITIVE`, and that pattern names authentication, authorisation, session, crypto and secret paths but nothing for data writes, so a fix round that adds a migration under `refute: false` gets no refuter.

**A project with no test or build command is never approved without a refuter.** With `refute: false`, `review-round` approves a clean verdict only when both gate lanes ran something, and a lane that honestly reports `ran: []` is missing. A repository with no build step, or no test runner, therefore gets `approved: false` from every lanes-only review, however often the lead runs the gates itself afterwards. There is no way yet to declare a gate absent for a project; the lead reads `gatesMissing` and the next step, which say so, and records its own gate run in its handoff.

## Skills

**`using-memory` is not in the fleet.** Its canonical copy is `agent-memory-js/plugin/skills/using-memory`, beside the hooks it documents, so the commit that changes the behaviour is the commit that updates the doc - the same co-location rule that makes `skills/glossary` canonical here. That text says "this plugin's hooks auto-recall", which is false for fleet agents: they reach memory through the connector with no hooks, and only the lead and `researcher` write. Bringing it in means an adaptation plus adding it to ten bodies, the roster, contract section 1.4 and the roster-contract allowlist, and that is its own piece of work. Until then the labelling convention rides in the two bodies that write (design section 6).
