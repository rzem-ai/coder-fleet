CF-207 replaces the old board with a new package at `claude/coder-fleet/boards/` (plural; the old one is `board/`). Group A (CF-207.2, reviewed 2026-11-14) is storage only: `~/.config/boards/<PREFIX>/`, key recorded in config.yml (normalised origin URL or real path of the git common dir), ids.json high-water mark, events.log. It is not wired into any hook yet; MCP, web UI and the `boards` binary come in later groups (G ships the CLI/binary, B owns locks and atomic writes).

**Why:** the spec (docs/specs/CF-207.md on the state branch) assigns concurrency (rekey race, allocateId read-modify-write, non-atomic config writes) to group B, so a group A review should not block on them. CF-207.3 criterion #7 now owns the unlocked re-key (lock only).

**How to apply:** check-all runs it as section `boards` via `bun test --timeout=60000` with no install; check-all-ci-bun and check-all-lock scratch trees list it. Settled at the human's word on 2026-11-14: folder named by prefix, prefix immutable and machine-unique, one board per repo. Round 2 (lead's default): ssh and scp-like hosts go through `ssh -G` (src/ssh-host.ts, 2 s timeout, falls back to the host as written); tests use a stub ssh on PATH from test/fixtures.ts (STUB_SSH_MODE=fail|slow), never the account's config. Round 3 (e419aad4, approved with follow-ups, 49 boards tests): keysFor returns urlSettled=false when ssh was asked about a plain host and returned null; resolveBoard then skips the re-key. That guard covers the re-key only: createBoard/assertCanCreate still record an unsettled alias key, and a transient lookup failure makes a URL-keyed board look absent, so `init` then makes a second board. Routed as a follow-up for the human (round 3 was the last under the cap). Path-case folding of remote paths is still an open decision.
