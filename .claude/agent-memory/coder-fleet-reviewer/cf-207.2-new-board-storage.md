CF-207 replaces the old board with a new package at `claude/coder-fleet/boards/` (plural; the old one is `board/`). Group A is CF-207.2, merged as 3a1b1094 and released in v0.59.0, and it is storage only. That covers `~/.config/boards/<PREFIX>/`, the key recorded in config.yml (the normalised origin URL, or the real path of the git common dir), the ids.json high-water mark and events.log. It also gives hooks `boardForHook` in src/hook-board.ts, which says "no board" once per session through a marker under TMPDIR. Nothing wires it into a hook yet. The MCP tools, the web UI and the `boards` binary come in later groups: G ships the CLI, the binary and the hook registration, and B owns locks and atomic writes.

**Why:** the spec (docs/specs/CF-207.md on the state branch) gives concurrency to group B, including allocateId's read-modify-write and the non-atomic config writes, so a group A review shouldn't block on them. Review rounds 2 and 3 added `ssh -G` alias keying and a urlSettled re-key guard. On 14 Nov 2026 the human cut keying back to the simplest version (spec criterion 5: no re-key), and the merge carries neither. A host is keyed as written, so an ssh alias gets its own board (an accepted cost), and a path-keyed board stays the repo's after the repo gains an origin.

**How to apply:** check-all runs the package as section `boards` via `bun test --timeout=60000`, with no install; at CF-207.9's head that was 44 tests across 8 files. Don't raise alias keying or re-key races against this package, since both were cut on purpose. Settled at the human's word on 2026-11-14: the folder is named by the prefix, the prefix is immutable and unique on the machine, and there is one board per repo. `findByKey` throws when two boards claim one key, so every caller of `resolveBoard` must expect a throw, hooks included. See [[cf-207.9-session-start-reminders]].
