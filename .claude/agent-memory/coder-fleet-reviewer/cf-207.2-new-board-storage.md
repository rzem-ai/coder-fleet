CF-207 replaces the old board with a new package at `claude/coder-fleet/boards/` (plural; the old one is `board/`). Group A (CF-207.2, reviewed 2026-11-14) is storage only: `~/.config/boards/<PREFIX>/`, key recorded in config.yml (normalised origin URL or real path of the git common dir), ids.json high-water mark, events.log. It is not wired into any hook yet; MCP, web UI and the `boards` binary come in later groups (G ships the CLI/binary, B owns locks and atomic writes).

**Why:** the spec (docs/specs/CF-207.md on the state branch) assigns concurrency (rekey race, allocateId read-modify-write, non-atomic config writes) to group B, so a group A review should not block on them. CF-207.3 criterion #7 now owns the unlocked re-key (lock only).

**How to apply:** check-all runs it as section `boards` via `bun test --timeout=60000` with no install; check-all-ci-bun and check-all-lock scratch trees list it. Settled at the human's word on 2026-11-14: folder named by prefix, prefix immutable and machine-unique, one board per repo. Round 2 (2026-11-14, lead's default): ssh and scp-like hosts go through `ssh -G` (src/ssh-host.ts, 2 s timeout, falls back to the host as written); tests use a stub ssh on PATH from test/fixtures.ts, never the account's config. Round 2 finding: that fallback makes the key environment-dependent, and resolveBoard's one-time path-to-URL re-key records whatever key it got, so a failed lookup at that moment re-keys to the alias for good. Check later rounds for a guard. Path-case folding of remote paths is still an open decision.
