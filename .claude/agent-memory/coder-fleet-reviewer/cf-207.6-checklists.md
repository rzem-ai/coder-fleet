CF-207.6 adds `src/checklists.ts` (own items first, then live `config.yml` `defaults.{criteria,dod}`, one 0-based number; default ticks in `defaultsTicked` by text), `src/dependencies.ts` (`dependenciesDone`, deleted dependency never finished) and CLI `show/add/tick/remove/depend/undepend/list --ready`. Round 1 at 265e01c5 (2026-11-14).

Settled in round 1: anyone may tick an Action for Human through the CLI (and later MCP). Spec 49 lists "add and tick Actions for Human" among agent operations and says the CLI offers the same. Spec 22 says ticking never moves a column, and spec 27 releases the card once every action is ticked. Spec 39's "no move other than the web UI override" constrains moves while one is unticked, not who ticks. No remove of actions, no cycle check, and Done cards showing new defaults unticked all match the spec as written.

**Why:** the brief raised an automated security flag on CLI tick, and the next group (D card gate, G MCP) builds on these functions.

**How to apply:** don't re-raise CLI ticking as a spec breach. When reviewing group D, check that the card gate reads `checklist()` (defaults included), not `card.criteria`/`card.dod` raw. Prose in actions.ts and the README saying only "the human" ticks was raised as Low. See [[cf-207.4-board-columns]].
