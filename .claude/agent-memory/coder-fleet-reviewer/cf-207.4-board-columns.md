CF-207.4 adds the eight columns (`boards/src/columns.ts`) and a checked `moveCard` that reads `from` off the card under `updateCard`'s lock. That settles CF-207.7's caller-`from` follow-up and CF-207.3's writeCard-snapshot trap for moves. It also adds a source-keyed rule table (hook, mcp, cli, web), Next ordering by `rank`, focus files and agent bindings in `src/focus.ts`, and four unregistered hook entry points (group G registers them).

Round 1 (2026-11-14, request changes) had two must-fixes. An isolated coder's SubagentStart cwd is its own worktree ([[subagent-start-cwd]]), so `readFocus(cwd)` bound nothing. The state root was a predictable shared `/tmp` name whose focus text reached additionalContext.

Round 2 (2026-11-14, head 32fd38ae, request changes). Suite green, 132.0 s, boards 99 pass. Settled: the state dir is `$XDG_STATE_HOME/coder-fleet-boards` or `~/.local/state/coder-fleet-boards`, 0700, refused when it is a symlink, foreign-owned or group/other-writable, written by writeAtomic, and focus text is shape-checked by `looksLikeCardId`. The lead's defaults are also settled: (a) an unticked action holds a start wherever the card is, (b) a focus on Done or Released binds nothing, (c) a Blocker never moves a card out of Released. `addActions` writes every Blocker before one move.

The open must-fix is that `onAgentStart` reads the focus at `CLAUDE_PROJECT_DIR || cwd`, while `pre-agent.ts` (the `Board-Item:` writer) and `session-start.ts` (the clearer) still key on the event's cwd. When a lead `cd`s into a linked worktree, the spawn's focus lands where SubagentStart never reads, so the agent binds to the main checkout's earlier focus. `docs/limits.md` records that a cd moves the PreToolUse cwd but not CLAUDE_PROJECT_DIR. The "two checkouts" test only passes because it gives one session id two project dirs. There are two Lows. A non-refusal error from the focus clear is rethrown into session-start's outer catch, which drops both reminders silently (round 1 logged the error and kept them). The mode check would refuse every dir on Windows, where the uid check is already skipped (unverified). One follow-up: `takeNext` (the CLI's next) still offers a card that default (a) holds.

**Why:** later CF-207 groups (D gates, E actions, G registration) build on this move function and binding.

**How to apply:** on round 3, check that writer, clearer and reader key on one base, and that a test runs `pre-agent` with cwd in a linked worktree and project = repo, then binds. Don't re-raise the settled items above, or the mechanical lane's `|| 0` note. See [[cf-207.7-event-trail]] and [[cf-207.3-board-locks]].
