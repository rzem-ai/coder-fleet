CF-207.4 adds the eight columns (`boards/src/columns.ts`) and a checked `moveCard` that reads `from` off the card under `updateCard`'s lock. That settles CF-207.7's caller-`from` follow-up and CF-207.3's writeCard-snapshot trap for moves. It also adds a source-keyed rule table (hook, mcp, cli, web), Next ordering by `rank`, focus files and agent bindings in `src/focus.ts` under `stateRoot()` (`$TMPDIR/coder-fleet-boards-<uid>`), and four unregistered hook entry points. Round 1 (2026-11-14): suite green (132.5 s, boards 93 pass across 12 files), verdict request changes.

Round 1 had two must-fixes. First, `onAgentStart` binds from `readFocus(cwd)`, but an isolated coder's SubagentStart cwd is its own new worktree ([[subagent-start-cwd]]), so it binds to nothing for good; the worktree test sends the main checkout as cwd. Second, the state root is a predictable `/tmp` name on Linux, where TMPDIR is usually unset. It is made with default modes and no owner check, `setFocus` follows a planted symlink, and session-start echoes the focus file's first line into additionalContext. The old hooks keep this state under `~/.local/state/coder-fleet` with umask 077.

There were two follow-ups. A Blocker on a Draft card stays in Draft, so it never reaches the human queue, and a later start from Backlog ignores the open action. Today's stale-focus guard is dropped: a focus on a Done card binds, and a Blocker then reopens it, Released included, which goes against spec 38.

**Why:** later CF-207 groups (D gates, E actions, G registration) build on this move function and binding.

**How to apply:** on round 2, check that the binding test sends the agent's worktree as the SubagentStart cwd. Check that the state root is private: 0700, owner-checked, or moved under the user's state dir. Check that the focus text is validated before it is echoed. Don't re-raise the mechanical lane's `|| 0` note: `NaN || 0` is 0, and the stable sort over `listCards`' id order does sort unranked cards by id. See [[cf-207.7-event-trail]] and [[cf-207.3-board-locks]].
