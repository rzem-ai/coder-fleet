CF-207.4 adds the eight columns (`boards/src/columns.ts`) and a checked `moveCard` that reads `from` off the card under `updateCard`'s lock. That settles CF-207.7's caller-`from` follow-up and CF-207.3's writeCard-snapshot trap for moves. It also adds a source-keyed rule table (hook, mcp, cli, web), Next ordering by `rank`, focus files and agent bindings in `src/focus.ts`, and four unregistered hook entry points (group G registers them).

Round 1 (2026-11-14, request changes) had two must-fixes. An isolated coder's SubagentStart cwd is its own worktree ([[subagent-start-cwd]]), so `readFocus(cwd)` bound nothing. The state root was a predictable shared `/tmp` name whose focus text reached additionalContext.

Round 2 (head 32fd38ae, request changes) settled the private state dir (0700, symlink, foreign-owned and group-writable refused, writeAtomic, `looksLikeCardId`) and the lead's defaults: (a) an unticked action holds a start wherever the card is, (b) a focus on Done or Released binds nothing, (c) a Blocker never moves a card out of Released. Its must-fix was the key split: the reader used CLAUDE_PROJECT_DIR while the `Board-Item:` writer and the session-start clearer used the event cwd.

Round 3 (head 9003bf75, the last under the cap, approved). `focusBase(cwd, env)` returns CLAUDE_PROJECT_DIR when it is a git checkout, else cwd, and all three hooks use it. The test with the lead cd'd into a linked worktree kills a revert of each of the three. Session-start now logs a non-refusal clear error to stderr and keeps the reminders. `takeNext` skips a card with an open Action for Human. The suite was green at 155.2 s, with 102 boards tests. Two Lows were raised. First, `cli.ts:78` still prints "Next and Backlog are empty" when they hold only held cards, and the usage line and README CLI row omit the skip. Second, the `subagent-start.ts` and `pre-agent.ts` headers still describe a cwd-keyed focus. The mechanical lane raised that the chmod test has no root guard.

**Why:** later CF-207 groups (D gates, E actions, G registration) build on this move function and binding.

**How to apply:** don't re-raise focusBase, the defaults, the state dir or the key split. A session launched outside any checkout falls back to cwd. It never clears the repo it later cds into, so an unflagged spawn there can bind to an earlier session's card. That matches the old board, which is also per-clone and never cleared from a non-repo start, so it is no defect against criterion 7. When reviewing group G, also check that the MCP or CLI focus setter (criterion 49's "bind focus") goes through focusBase. See [[cf-207.7-event-trail]] and [[cf-207.3-board-locks]].
