description: How the reviewer scope hook treats gate commands in coder-fleet - redirections, $( ), git tag and git worktree refused; gates need the `cd /abs && bash ...` form
metadata:
  type: reference
---

The reviewer's scope hook refuses any gate command carrying `>` or `2>&1` (it reads them as file writes), and refuses `git worktree list` and `git tag -l` as non-read-only verbs. It refuses any `$(` or backtick, even inside a read like `cat "$(grep -l ...)"`: run the inner command alone, then Read the path. A gate must be written `cd /abs/worktree && bash claude/evals/lib/<gate>.sh`; `cd x; bash ...` with a semicolon is refused. The output of a bare gate is persisted to a tool-results file you can grep. Piping a gate through `| tail` is allowed but masks the gate's exit code, so run the gate bare when the exit code matters.

**Why:** observed 2026-11-08 reviewing CF-183.1 and CF-179 round 2; several attempts were refused before the right form ran.

**How to apply:** run each declared gate as `cd <worktree> && bash <gate>` from the review worktree root. List worktrees with `ls .claude/worktrees/`, and read release versions with `git log --format=%s -- claude/coder-fleet/.claude-plugin/plugin.json` instead of git tag. `cmp` and `diff` on files are refused as executing code; compare files with the Read tool instead. The full suite took about 80 to 95 s on the human's machine at that time. On 2026-11-10 (CF-185) the suite waited 230 s on another run's check-all lock and totalled 318.7 s, so the 480000 ms timeout is load-bearing; reviews in a workflow often overlap the tests lane's own run. A worktree that already has `claude/coder-fleet/board/node_modules/` shows it as `!!` in `git status --ignored` before the run, so it isn't a run artefact. The memory Write the hook accepts may be under the main checkout, not the review worktree; on 2026-11-08 the worktree path was refused. Seen 2026-11-10 (CF-186): `2>/dev/null` on a plain grep is refused like any `>`; a grep pattern holding `.command("view` is parsed as a command and refused, so keep grep patterns to plain tokens; `; echo $?` after a gate is refused, but a bare gate that exits non-zero shows as a tool error, so no error means exit 0. `sleep` (and so any until-loop poll) is refused: run check-all with run_in_background, run the three single gates in the foreground meanwhile, and Read the output file once the completion notification arrives (CF-186 round 2, 2026-11-10). CF-187.1 (2026-11-10): `git branch` (even `-a --contains`) is refused like `git worktree`; find the review worktree with a loop of `git -C <dir> log -1 --format=%H` over `.claude/worktrees/agent-*`. `board-hook-contract.sh` prints `fatal: cannot change to .../live/.claude/worktrees/coder-fleet-state` lines on a green run; they're fixture noise, not a failure. CF-186 merge review (2026-11-10): `git merge-base` is refused as non-read-only; use `git diff A...B --stat` (three dots) for the merge-base side and `git log A..B` for incoming commits. A command line holding a variable named `W` plus `sed` trips the sed w/W/e check; use `head | tail` to pick a line. A lock wait counts toward check-all's printed total, so a total over 180 s after "lock taken after N s" is not a budget breach. Release review v0.50.0 (2026-11-10): `2>&1` on a plain git command is refused too; tag names still resolve as refs, so `git log v0.49.0..<base>` lists what a release carries and `git log -1 --format='%h %d' v0.49.0` shows the tag. Check that range against the subject's item list, since the subject is the only release record.
