name: gate-run-quirks
description: How the reviewer scope hook treats gate commands in coder-fleet - redirections, $( ), git tag and git worktree refused; gates need the `cd /abs && bash ...` form
metadata:
  type: reference
---

The reviewer's scope hook refuses any gate command carrying `>` or `2>&1` (it reads them as file writes), and refuses `git worktree list` and `git tag -l` as non-read-only verbs. It refuses any `$(` or backtick, even inside a read like `cat "$(grep -l ...)"`: run the inner command alone, then Read the path. A gate must be written `cd /abs/worktree && bash claude/evals/lib/<gate>.sh`; `cd x; bash ...` with a semicolon is refused. The output of a bare gate is persisted to a tool-results file you can grep. Piping a gate through `| tail` is allowed but masks the gate's exit code, so run the gate bare when the exit code matters.

**Why:** observed 2026-11-08 reviewing CF-183.1 and CF-179 round 2; several attempts were refused before the right form ran.

**How to apply:** run each declared gate as `cd <worktree> && bash <gate>` from the review worktree root. List worktrees with `ls .claude/worktrees/`, and read release versions with `git log --format=%s -- claude/coder-fleet/.claude-plugin/plugin.json` instead of git tag. `cmp` and `diff` on files are refused as executing code; compare files with the Read tool instead. The full suite took about 80 to 95 s on the human's machine at that time. On 2026-11-10 (CF-185) the suite waited 230 s on another run's check-all lock and totalled 318.7 s, so the 480000 ms timeout is load-bearing; reviews in a workflow often overlap the tests lane's own run. A worktree that already has `claude/coder-fleet/board/node_modules/` shows it as `!!` in `git status --ignored` before the run, so it isn't a run artefact. The memory Write the hook accepts may be under the main checkout, not the review worktree; on 2026-11-08 the worktree path was refused. Seen 2026-11-10 (CF-186): `2>/dev/null` on a plain grep is refused like any `>`; a grep pattern holding `.command("view` is parsed as a command and refused, so keep grep patterns to plain tokens; `; echo $?` after a gate is refused, but a bare gate that exits non-zero shows as a tool error, so no error means exit 0. `sleep` (and so any until-loop poll) is refused: run check-all with run_in_background, run the three single gates in the foreground meanwhile, and Read the output file once the completion notification arrives (CF-186 round 2, 2026-11-10). CF-187.1 (2026-11-10): `git branch` (even `-a --contains`) is refused like `git worktree`; find the review worktree with a loop of `git -C <dir> log -1 --format=%H` over `.claude/worktrees/agent-*`. `board-hook-contract.sh` prints `fatal: cannot change to .../live/.claude/worktrees/coder-fleet-state` lines on a green run; they're fixture noise, not a failure. CF-186 merge review (2026-11-10): `git merge-base` is refused as non-read-only; use `git diff A...B --stat` (three dots) for the merge-base side and `git log A..B` for incoming commits. A command line holding a variable named `W` plus `sed` trips the sed w/W/e check; use `head | tail` to pick a line. A lock wait counts toward check-all's printed total, so a total over 180 s after "lock taken after N s" is not a budget breach. Release review v0.50.0 (2026-11-10): `2>&1` on a plain git command is refused too; tag names still resolve as refs, so `git log v0.49.0..<base>` lists what a release carries and `git log -1 --format='%h %d' v0.49.0` shows the tag. Check that range against the subject's item list, since the subject is the only release record. CF-192 (2026-11-11): from v0.51.0 a review-mode reviewer's Bash is refused any command naming `~/.claude/projects` or the state dir, so grepping a persisted gate output under `.../tool-results/` with Bash stops working; use the Grep or Read tool on it instead (neither reaches the scope hook). A bare `ls <dir>` with a `2>&1` or `| head` is refused, so plain `ls -la <dir>` works. The suite waited 101 s on a concurrent break lane's lock and totalled 277 s. CF-193.1 (2026-11-12, installed plugin 0.50.0): no Grep tool in a workflow reviewer session, and Bash grep on `~/.claude/projects/.../tool-results/` was allowed, so the v0.51.0 refusal is not live until that release installs. `python3 -c`, `fold` and `$(` refused as before. CF-183.2.1 round 2 (2026-11-12): the mechanical lanes run mypy, ruff and py_compile in the review worktree and leave ignored `.mypy_cache/`, `.ruff_cache/` and `hooks/lib/__pycache__/`; compare their mtimes (`ls -laT`) with the suite's start before calling them a gate artefact. CF-183.2 merge review (2026-11-12): process substitution `<(...)` is refused, and so is any `>` even to /dev/stdout; zsh reads `echo ===` as equals-expansion and errors, so use `echo ---` as a separator. For "did the merge hand-edit anything", `git show --remerge-diff <merge>` is the answer: it lists every file whose result differs from git's automatic merge, conflicted or not, so there's no need to diff file lists. CF-193.4 (2026-11-12): `cat <file> 2>&1` on a non-gate read is refused like any `>`; run_in_background for check-all plus foreground single gates worked again (suite 109 s, no lock wait). From CF-193.4 review-round's verdict schema requires a `gates` field of gate lines; a review of that card itself runs on the base workflow, whose schema lacks it. `git diff --word-diff=plain A B -- f | grep -o` compares a long one-line paragraph word for word. CF-192 merge review (2026-11-12): `md5`/hashing is refused as executing code; to prove each side's hunks survived a clean merge, count `git diff -U0 base sideA -- f | grep -cE '^[+-][^+-]'` against `git diff -U0 sideB merge -- f` (and the mirror pair) - equal counts plus no remerge-diff entry for the file is enough. Piping a single gate through `| tail` hid its exit code again; run every gate bare. Hooks matched within one event run in parallel in Claude Code, so entry order in hooks.json is not load-bearing. CF-193.4 round 3 (2026-11-12): piped scope-hook through `| tail` by habit yet again and lost its exit code - never pipe a gate. Running the single gates beside check-all slows it (200.7 s with no lock wait), so a total over 180 s then is not a budget breach. workflow-logic.mjs's `reviewDefaults` fills `worktree`/`head` into stubs that omit them, so a pre-CF-181 case still runs the real path. CF-190 (2026-11-12): `date` is refused as executing code; to tell a run artefact from a prior lane's, compare `ls -laT` mtimes against the worktree's checkout time (the tracked files' mtime) instead. An empty `claude/coder-fleet/board/tmp/` appears after a suite run but git does not list an empty dir, so `status --ignored` stays clean. CF-196 (2026-11-12): on APFS, reading a file under `claude/coder-fleet/commands/` makes the harness inject `commands/agents.md` as if it were an `AGENTS.md` (case-folded name); it is the `/agents` command body, not instructions to the reviewer. Suite plus the three single gates in parallel: 137.8 s, no lock wait. CF-200 (2026-11-12): `git config` and `git --version` are refused as non-read-only verbs; Read `.git/config` directly instead. A grep pattern holding the word `reset` is refused as a non-read; keep such words out of patterns. Suite waited 89 s on a lock and totalled 209.7 s. CF-201.1 round 2 (2026-11-12): piped scope-hook through `| tail` yet again, so its exit code went uncaptured. Run the bare gate and grep the persisted output afterwards. Suite 154.8 s.
