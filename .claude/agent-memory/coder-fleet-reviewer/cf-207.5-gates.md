Round 1 at a3f5df1b (2026-11-14): request changes. Must fix was `post-push.ts` calling `releaseCatchUp` with onBaseOnly=false, so any in-session push started every unclaimed fetched tag on origin, skipping the session-start off-base hold.

Round 2 at 0a6d375c (2026-11-14): `releaseCatchUp(..., only: "on-base" | Set)`, post-push passes `pushedNames(command)`. Gap then: repository word and option values counted as tag names.

Round 3 at 112f89c4 (2026-11-14): pushedNames skips the first non-option word (repository), the value after `-o/--push-option/--receive-pack/--repo/--exec`, ends options at `--`, reads `tag v1`. `claimedTags(board)` drops releases whose release-finished is `not started`; it is read under the releases lock in startRelease, and the runner writes the not-started release-finished under the same lock, so no double start. Retry is bounded by session starts and pushes naming the tag, not a loop. The test pins `claimedTags` directly (fixture sets tagObject = release id), not the wiring in releaseCatchUp/startRelease. Residual word risks left as contrived: refspec words that are branch names (`HEAD`, `main`) match only a local tag of that name; short-option cluster `-fo val` counts `val`; `(… git push origin v1)` reads `v1)` (false negative only).

Settled in round 1, don't re-raise: a card with no checklist items passes the card gate (spec 29 vacuous); two releases on one commit running twice is consistent with spec 27; no run timeout is not a spec defect; the round 1 existing-test edits follow from spec 23/29. Round 1 Lows still open: pid reuse after reboot holds off spec 34's restart; unclaimed tags make every start call ls-remote.
