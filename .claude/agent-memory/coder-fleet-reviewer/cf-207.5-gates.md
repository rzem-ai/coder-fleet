CF-207.5 adds `src/gates.ts` (cardGate, GATE_FROM Backlog/Next/In Progress, `[board:<id>]` marker), the card-gate and Released-final rules in `moves.ts` check() (web branch first, then `from === "Released"`, then unticked into Done, then Released only from Done), and `src/releases.ts` (releaseCatchUp, startRelease under `locks/releases.lock`, detached `test-runner.ts`, runDir under privateStateDir/runs). Hooks `post-push.ts` (PostToolUse on Bash) and `task-completed.ts` are not registered yet; registration is group G's. Round 1 at a3f5df1b (2026-11-14): request changes.

Round 1 must fix: `post-push.ts` calls `releaseCatchUp` with `onBaseOnly=false`, and releaseCatchUp walks every unclaimed local annotated tag with a `Cards:` line on origin, not only the tag being pushed. So the lead's session-start off-base guard is bypassed by any in-session `git push` (a fetched collaborator tag on an unmerged commit runs its test command). The README's reason, "a push in the session tags the session's own commit", is false for that loop.

Settled in round 1, don't re-raise: a card with no checklist items passes the card gate (spec 29 vacuous, README says so); two releases on one commit running twice is consistent with spec 27; no run timeout is not a spec defect; the four existing-test edits (columns, events, two hooks.test SubagentStop rows that send agent_type coder) follow from spec 23/29 and keep their pins. Lows raised: pid reuse after reboot holds off spec 34's restart; a missing test command or a failed `git worktree add` records a failed run and blocks Done cards; unclaimed tags make every push and start call ls-remote.

**Why:** group G registers these hooks and the MCP/web routes build on moveCard's order of checks.

**How to apply:** in round 2 check the post-push path filters to the pushed tags or applies the on-base rule. In group G, check registration of PostToolUse and TaskCompleted. See [[cf-207.6-checklists]] and [[cf-207.4-board-columns]].
