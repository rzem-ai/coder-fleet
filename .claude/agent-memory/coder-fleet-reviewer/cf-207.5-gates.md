CF-207.5 adds `src/gates.ts` (cardGate, GATE_FROM Backlog/Next/In Progress, `[board:<id>]` marker), the card-gate and Released-final rules in `moves.ts` check() (web branch first, then `from === "Released"`, then unticked into Done, then Released only from Done), and `src/releases.ts` (releaseCatchUp, startRelease under `locks/releases.lock`, detached `test-runner.ts`, runDir under privateStateDir/runs). Hooks `post-push.ts` (PostToolUse on Bash) and `task-completed.ts` are not registered yet; registration is group G's.

Round 1 at a3f5df1b (2026-11-14): request changes. Must fix was `post-push.ts` calling `releaseCatchUp` with onBaseOnly=false, so any in-session push started every unclaimed fetched tag on origin, skipping the session-start off-base hold.

Round 2 at 0a6d375c (2026-11-14): fix makes `releaseCatchUp(..., only: "on-base" | Set)`, post-push passes `pushedNames(command)` (every non-dash word after `push`, quotes and `+` dropped, `src:dst` split, `refs/tags/` stripped), matched against `refname:strip=2`. `--tags`/`--follow-tags` start nothing by design (README says so). Remaining gap: the repository word (`origin`) and option values are added to the set, so a fetched tag named `origin` still bypasses the hold. A tag sharing a branch's name is mostly stopped by git's own "matches more than one" push error. The low (missing test command or failed worktree add) now records `not started` and moves nothing, but the tag stays claimed forever with no retry and no session notice (follow-up). The "never reached origin" test now passes on the name filter alone.

Settled in round 1, don't re-raise: a card with no checklist items passes the card gate (spec 29 vacuous); two releases on one commit running twice is consistent with spec 27; no run timeout is not a spec defect; the round 1 existing-test edits follow from spec 23/29. Round 1 Lows still open: pid reuse after reboot holds off spec 34's restart; unclaimed tags make every start call ls-remote. The `--tags` to named-push test edit in round 2 follows from the fix.

**Why:** group G registers these hooks and the MCP/web routes build on moveCard's order of checks.

**How to apply:** in a round 3, check pushedNames skips the repository argument. In group G, check registration of PostToolUse and TaskCompleted. See [[cf-207.6-checklists]] and [[cf-207.4-board-columns]].
