CF-207.9 adds `claude/coder-fleet/boards/src/hooks/session-start.ts`. In a repo with a board it prints spec 66's two sentences, verbatim, as SessionStart `additionalContext` for every source (startup, resume, clear, compact). With no board it passes on `boardForHook`'s once-per-session message. There is deliberately no Stop hook: a Stop hook can only reach the agent by continuing the turn, and spec 65 forbids blocking a stop. Round 1 (2026-11-14) was approved with follow-ups and a green suite.

**Why:** the lead's comment on the card hands registration in hooks.json to group G. Group G has no card yet (it gets filed as the first card on the new board), and none of spec criteria 48 to 57 names registering the new board's hooks. Holding the registration back is right: wiring it in now would tell every session to ask for a new board while the old one is still live.

**How to apply:** don't re-raise the SessionStart-only design or the held-back registration. When reviewing group G, check two things: that it registers this hook with no matcher that drops `compact`, and that the hook runs without bun on an installed plugin. Round 1 raised two Lows. First, the hook has no top-level guard, though every plugin SessionStart hook "never exits non-zero", and `boardForHook` can throw. Second, the test reuses one session id and spawns the hook from input.cwd, so a hook that dropped session_id would still pass. See [[cf-207.2-new-board-storage]] for the package itself.
