Settled on CF-193.4 (2026-11-12, lead decisions on the card after round 1): review-round's gate run is the reviewer's `gates` lines, each labelled with the `head` it ran at; a non-zero exit goes under `gatesFailed` and makes `approved` false but does not commission a fix round on its own (a red gate under an approve verdict stops `clean` with a "Not an approval" prefix); a `prose-only fix` stop puts "the gates at the fix head <sha>" first in `gatesMissing` and tells the lead to run them there or read CI. lead.md's prose-only wording was deliberately left for CF-193.5, which rewrites lead.md on top of this branch. Having the pin lane read the gates block so a silently skipped gate lands in `gatesMissing` was left as a proposal.

**Why:** these were the lead's calls on the card, so a later review should not raise them as defects.

**How to apply:** when reviewing CF-193.5, check lead.md's prose-only step now says to run the gates at the fix head (the next-step text is quoted verbatim on the CF-193.4 card). Watch for docs/limits.md still describing the removed "gate lanes" (line ~107 at 107fd11). See [[cf-192-reviewer-modes-settled]]. Round 3 (88b49f1..edd940f, after the rebase onto main): `proseOnly` now also rejects any `isStateFile` path, so a fix adding agent memory gets the narrow round that blocks on it; limits.md's "gate lanes" paragraph was rewritten to match lines ~2353-2357.
